# Elasto Fuse art

Generated by `scripts/elasto-fuse-art.ts` (edit the tables there, then rerun it; this file is rewritten on every run). The script calls the OpenAI image API with `OPENAI_API_KEY` from the environment, caches the raw images in `node_modules/.cache/elasto-fuse-art/`, and fits them in a headless Chromium canvas to the exact sizes below in `public/games/elasto-fuse/art/v1/`, with `manifest.json` beside them. The renderer draws a procedural fallback for any file that is missing.

Look: a side-view motorbike trials game in the Fuse neon style, mechanically modelled on Elasto Mania (a springy dirt bike on polygon terrain; collect every apple, then touch the flower). The art is original; no Elasto Mania art, names or logos are used.

## Geometry

Sprites are drawn at 240 px per world unit. The bike faces right in every sprite (the code mirrors it), in a flat side view with no perspective, ground or shadow. The code hue-shifts the cyan accent per player at load, so the bike and rider sprites use cyan (#16e7ff) as their only accent on dark graphite, white and neutral grey.

Rest layout in world units, x right, y up, origin at the bike frame's centre: rear wheel hub (-0.85, -0.6), front wheel hub (0.85, -0.6), wheel radius 0.4, rider head centre (0, 0.44) with radius 0.24. The frame's body stays within x -0.75 to 0.75 and y -0.45 to 0.35; the code draws the front fork and the rear swingarm as lines from the frame to the moving wheels. The torso and the four limb pieces lie horizontally and hang between two joints, listed in `manifest.json` as `joints`.

Opaque art is WebP (quality 0.9, about a tenth of the PNG's size); sprites are PNG with real transparency. A sprite is trimmed of its transparent margin (pixels with alpha of 24 or less are cleared, which removes stray halos) and scaled evenly into its box, centred, so a round piece keeps its centre and a limb's joint line stays on the image's horizontal midline. The ground and the sky are made to tile by cross-fading each with a copy of itself shifted by half its size, along both axes for the ground and along x for the sky.

## Rerunning

```sh
pnpm exec tsx scripts/elasto-fuse-art.ts                               # every asset
pnpm exec tsx scripts/elasto-fuse-art.ts --only frame --n 3            # three candidates, written to the cache for review
pnpm exec tsx scripts/elasto-fuse-art.ts --only frame --pick frame=2   # fit the chosen candidate into place
pnpm exec tsx scripts/elasto-fuse-art.ts --sheet                       # contact sheet of the fitted files
pnpm exec tsx scripts/elasto-fuse-art.ts --manifest                    # manifest and this file only
```

Sources run in three stages: first the pieces with no reference image, then the limbs (they take the fitted `torso.png` as a reference, so they share its suit), then the hero. The hero's first reference is `assembled.png`, the fitted parts assembled into a bike at the rest layout, which the script writes to the cache with `contact-sheet.png` on every run. Regenerate the limbs after the torso changes, and the hero after any bike or rider piece, the apple, the flower or the sky changes.
