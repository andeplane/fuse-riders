# Retro games

Start > Programs > Games > Retro Games holds eight classics: four shareware DOS games booted in js-dos, two open source web games in a frame of their own, and Minesweeper and Solitaire written for FuseOS in React. The yellow **DOS Games** folder on the desktop (also "Open DOS Games folder" in that menu, `?open=dosgames` and `dosgames` in Run) opens them as an Explorer-style folder window (`packages/fuseos/src/retro/RetroFolderWindow.tsx`): the four DOS games first, the Windows games (Minesweeper, SkiFree, Micropolis, Solitaire) in a group under them; a double click starts a game, and View > Details shows the licence table below in the window itself.

The playable files live under `public/fuseos/retro` and the js-dos player under `public/fuseos/jsdos`; the licence texts live in `licenses/` next to this file. Everything is served from the site's own origin, under any base path: GitHub Pages serves the site at `/fuse-riders/`, a static preview at `./`, and the player page resolves the emulator core and the bundles relative to itself, so both work without a rebuild of the assets. Nothing is loaded from js-dos.com or dos.zone (`noCloud`). Nothing here is written by the FuseOS authors except this document, the `.jsdos/dosbox.conf` bundle configs, the js-dos player page and the two native games.

## Shareware terms

The four DOS games are the shareware episodes their publishers released for free distribution. id Software's and Apogee's vendor documents and 3D Realms' licence allow individuals and free online services to pass the unmodified shareware on without charge; the bundles contain each archive's files unmodified, plus a `.jsdos/dosbox.conf` that mounts the folder and starts the game. No registered episodes are included. Read the licence files before redistributing this site commercially: rack, CD-ROM and paid distribution need written permission from the publishers.

## js-dos

The DOS games boot in [js-dos](https://js-dos.com) 8.4.1 by Alexander Guryanov (GPL-2.0, source at [caiiiycuk/js-dos](https://github.com/caiiiycuk/js-dos)). `scripts/fuseos/copy-jsdos.mjs` copies `js-dos.js`, `js-dos.css` and the DOSBox WebAssembly core (`emulators.js`, `wdosbox.js`, `wdosbox.wasm`, `wlibzip.js`, `wlibzip.wasm`) from the npm package into `public/fuseos/jsdos`, patching the loader so the core is loaded by URL from our origin rather than through `eval` and a `blob:` worker. The bundles are named `.jsdos.wasm` because some static hosts reject `.jsdos` and `.zip` uploads but accept `.wasm`; js-dos ignores the extension.

The player runs in `public/fuseos/jsdos/player.html?bundle=<name>`, a page of its own inside the game window's iframe, because js-dos ships a global stylesheet and keyboard handling that must not leak into the desktop. `player.js` resolves `../retro/<name>.jsdos.wasm` and `emulators/` relative to its own URL, which is what makes the page base-independent. It also wraps `navigator.keyboard.lock()`: js-dos locks Escape and W so they reach the game, but Chromium only allows keyboard lock from a top-level page and rejects the call inside a frame, an unhandled rejection js-dos would otherwise log on every start; the player keeps the call where it works and swallows the rejection where it does not.

## SkiFree

skifree.js is vendored as built by its author (`dist/skifree.js`, the sprite sheets and stylesheets). `index.html` is ours: the analytics snippet and the GitHub banners were dropped.

## Micropolis

micropolisJS is a port of Micropolis, the GPL release of the 1989 city simulator. It is built from source with the repo's own webpack toolchain by `scripts/fuseos/vendor-web-games.py` and copied here with its `LICENSE`, `COPYING` and `MicropolisPublicNameLicense.md`. Changes from upstream: the build id is `vendored`, the Twitter widget is removed and the inline `data-hasscript` script moved to `hasscript.js`.

Micropolis is a registered trademark of Micropolis Corporation (Micropolis GmbH) and is licensed here as a courtesy of the owner under the [Micropolis Public Name License](https://www.micropolis.com). The game is not affiliated with Electronic Arts; the name SimCity is an Electronic Arts trademark and is not used for it.

## Solitaire

Solitaire is Klondike written for FuseOS in React (`packages/fuseos/src/retro/solitaire`): the Windows 98 rules and scoring, draw one or three, Standard, Vegas or no scoring, a timer, Undo, twelve card backs and the bouncing card cascade. No Microsoft bitmaps are used. The card faces are Byron Knoll's Vector Playing Cards, released into the public domain and mirrored at notpeter/Vector-Playing-Cards; `scripts/fuseos/vendor-web-games.py --only solitaire` downloads the SVGs and rasterises the 52 faces with `rsvg-convert` (librsvg) into one sprite sheet, `public/fuseos/retro/solitaire/cards.png` (13 columns ace to king, 4 rows clubs, diamonds, hearts, spades, 142x192 px per card, twice the 71x96 card size). The card backs are drawn in SVG in `packages/fuseos/src/retro/solitaire/cardBacks.tsx`, in the spirit of the classic designs without copying them.

## Regenerating

The bundles, the vendored games and the js-dos player are committed; none of these run during `pnpm build`.

```bash
python3 scripts/fuseos/build-jsdos-bundles.py   # downloads the shareware archives into scripts/.shareware, writes the bundles and the licence texts
python3 scripts/fuseos/vendor-web-games.py      # needs node and npm for the Micropolis build and rsvg-convert for the Solitaire cards
pnpm fuseos:sync                                # copies js-dos (and Clippy) from node_modules after a version bump
```

`tests/fuseos-retro-games.test.ts` checks that every game in the catalogue has its files under `public/fuseos`, a row in the table above and its licence texts in `licenses/`.
