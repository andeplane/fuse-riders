# Independent review: action-log prototype design

Date: 2026-09-14. Scope: [ADR040](../adr/040-deterministic-action-replication.md), [design brief](../online/DETERMINISTIC-ACTION-LOG-BRIEF.md), and current `HostSession`, game step, checkpoint, runtime and peer transport boundaries. Tracking: [#82](https://github.com/andeplane/fuse-riders/issues/82).

## Disposition

Approve bounded implementation of the opt-in host-coordinated, reliable-transport prototype with the amendments below incorporated before live integration. This is a design review, not implementation or release acceptance. Full mesh agreement, remote speculative rollback, edge-only upstream input and deterministic replacement math are explicitly deferred; retaining those limits is a coherent first milestone rather than evidence that the complete brief has shipped.

The approach preserves the existing authority and accepted-input scheduler, while eliminating routine downstream geometry replication. Capturing resolved controls before `step()` is the right boundary: raw network commands alone cannot reconstruct bot decisions, freshness cancellation or the scheduler's separate handling of movement and bomb transitions. The existing host-refresh checkpoint decoder cannot serve replica bootstrap because it deliberately disconnects humans and clears charge.

## Required concrete amendments

1. **Define record order separately from simulation tick.** Give each journal operation a monotonically increasing stream sequence. Non-step commands can mutate state several times at the same tick. Specify the transaction as pending lifecycle operations, resolved held-control changes and ordered bomb commands, one shared game step, then post-step lifecycle operations such as disconnected-seat pruning and next-round start. Checkpoint and hash positions identify the complete operation sequence as well as tick; publication cannot expose half a transaction. Preserve player/map iteration order wherever game rules consult it. Per-player tick deltas remain an encoding choice and do not replace lifecycle ordering.

2. **Freeze resource bounds in bytes and age.** In addition to 400 retained operations and 100 operations per batch, cap encoded live journal retention at 2 MB and twenty seconds using an injected monotonic clock, and encoded action packets at 128 KiB. Cap checkpoint chunks at the stated 12 KB payload, 2 MB total, five-second assembly and one assembly per peer. Use explicit decoder collection/string/binary limits before semantic validation. Overflow invokes a newer checkpoint, never deletion followed by falsely acknowledged contiguous progress. If a single record exceeds its bound, fail the experimental stream visibly rather than repeatedly sending an impossible record. Bound checkpoint pumping to four chunks per publish and preserve the existing transport backpressure gate.

3. **Make consistency and recovery thresholds executable.** Compare canonical hashes every twenty committed simulation ticks and at every installed checkpoint. Track hash comparisons by exact stream position; comparing unlike ticks is not divergence. Allow at most two resync requests per second, but do not reset the assembly deadline on each chunk or progress notice. Three post-baseline hash mismatches within thirty seconds terminate the experimental stream visibly; recovery does not erase this rolling failure count. Lost history pauses replica advancement until a validated replacement checkpoint. A maximum of 100 replay steps applies to all operations processed in one call, not separately to each nested record.

4. **Keep presentation side effects single-sourced.** Retain the existing authoritative event messages for this prototype. Replica stepping derives state but must not independently dispatch audio, achievements, effects or other external callbacks; replay/bootstrap must not replay historical sounds. This avoids doubling the event callback already issued by `RoomRuntime`. Any later replacement of the event channel needs an explicit event identity/deduplication contract.

5. **Bind compatibility to simulation semantics.** Put a replay-rules identifier in the negotiated capability and checkpoint as well as a wire version. A MessagePack-compatible tuple does not establish compatible game rules. Reject an unknown identifier before replica mutation. Canonical serialization must distinguish simulation-relevant optional values and preserve authoritative map order or canonicalize that order in both execution and serialization. Sampled browser hashes qualify only the measured trace and engines.

6. **Keep upstream and prediction claims narrow.** The live prototype still transmits repeated held-state input and uses the current local movement predictor; the estimate of two records for a two-second turn therefore describes the proposed final action interface, not this first implementation's total traffic. Report downstream actions, controller projection, upstream commands, checkpoints and complete transport-envelope bytes separately. The prototype must visibly identify its requested mode and fail an incompatible opt-in request rather than silently claim action mode while using snapshots.

## Implementation review focus and evidence

Before calling the prototype reliable within its scope, inspect tests for join/rejoin, avatar/settings, host return-to-lobby/reset, bot add/remove, automatic next-round start, authority-grace `clear()`, invalid/expired release cancellation and seat reclamation. Each gameplay consequence must appear at its accepted boundary or be provably derived by the shared step. Validate checkpoint installation without mutation on rejection, including correct held aim/charge and non-persistent bomb commands; map/slot reuse must not redirect old records to a new rider.

Exercise duplicate, missing, reordered, corrupted, oversized and stale-generation records and chunks with typed injected clocks/transports; acknowledgement must follow atomic installation, never enqueue. Bootstrap and mode change while players charge/fire deserve direct regressions. Ensure a controller-only peer does not instantiate the game replica and that shared-TV mode still receives the fields required by controller aiming and status UI.

Run Node/Chromium/WebKit traces with exact canonical comparison at every committed tick, checkpoint suffix equivalence and deliberately injected divergence. A cross-engine mismatch blocks promotion; repeated automatic resync is not a passing determinism result. Run the existing release checks and isolated browser workloads specified in ADR040, retaining raw byte and CPU/frame measurements with source identity. New online protocol modules are not automatically included by the explicit online entries in `.c8rc.json`; include them in enforced coverage without lowering thresholds, and report runtime/transport/browser surfaces that remain outside coverage.

No public rollout, physical-phone acceptance, WAN qualification, durable replay archive or host failover is approved by this review.

## Reviewed numerical and retention amendment

The implementing agent reported an exact Chromium/WebKit replay mismatch at tick 63 in accumulated `distanceUnits`: `29.999999999999986` versus `29.99999999999999`, traced to the shared two-argument `Math.hypot` calculation. Approve introducing a shared `hypot2(x, y) = Math.sqrt(x*x + y*y)` for the game's bounded finite coordinate/velocity domain, used consistently by authority, replicas, bots and prediction. The helper must document that it is not a general overflow/underflow-resistant replacement for arbitrary-magnitude `Math.hypot`. For the bounded domain, explicit multiplication/addition order and correctly rounded square root remove this particular engine-dependent norm algorithm. The [ECMAScript 2025 square-root clause](https://tc39.es/ecma262/2025/multipage/numbers-and-dates.html#sec-math.sqrt) specifies rounding the mathematical square root to a Number; `Math.hypot` permits an implementation-approximated result.

This deliberately changes low-order simulation bits in the shared default game path as well as experimental replication. Use one numerical implementation rather than independently maintained replay/default physics. Bump checkpoint compatibility and replay-rules identifiers, retain the original failed trace and rerun game, collision, portal, gun/shell, prediction and exact cross-engine replay regressions. Preserve the old comparison as historical evidence; do not label the revised engine bitwise compatible with old checkpoints. This approval is for implementation, not evidence that the corrected trace has passed. Native trigonometry remains subject to cross-engine trace testing; a further observed difference blocks acceptance and needs another numerical decision.

Also approve 400 **simulation ticks** as the journal age bound, alongside the independent 400-operation and 2 MB encoded bounds. This supersedes this review's earlier request for twenty seconds measured by an injected monotonic clock. A paused game can retain the bounded journal longer in wall time without creating extra memory growth or admitting stale controls: input freshness/admission remains host-owned, and journal entries are already committed history. Checkpoint assembly deadlines, retries, mismatch windows and negotiation deadlines must continue to use monotonic elapsed time. Describe retention as simulation age, not a twenty-second wall-clock guarantee.

## Reviewed trigonometry amendment

The implementing agent subsequently reported WebKit rider/trail coordinate differences of approximately `3e-14` at ticks 1868/2313 after the norm change. These are a blocker to exact replay, not grounds for loosening the comparison. Approve implementation of pinned pure-JavaScript stdlib `sin`, `cos` and `atan2` through the shared numerical helper, conditional on inspection of the installed dependency graph and built browser artifact. Use explicit `lib/main.js` entries and ignore install scripts; lock transitive versions. Top-level explicit entries alone are insufficient because they still import their own dependencies through package names: inspect reachable implementations of argument reduction, kernels, `atan`, float-word access and special-value helpers for native-addon dispatch or implementation-approximated `Math` wrappers. The actual Node and browser execution paths must perform the same numeric operations.

The official [sine implementation](https://raw.githubusercontent.com/stdlib-js/math-base-special-sin/main/lib/main.js) and [cosine implementation](https://raw.githubusercontent.com/stdlib-js/math-base-special-cos/main/lib/main.js) are JavaScript adaptations of FreeBSD/fdlibm code retaining Sun notices. The official [atan2 implementation](https://raw.githubusercontent.com/stdlib-js/math-base-special-atan2/main/lib/main.js) instead identifies a Go implementation and retains its BSD notice; do not describe all three as the same fdlibm provenance. Preserve applicable license/notice material in distributed artifacts. Verify exact installed package versions and sources rather than assuming the mutable upstream `main` matches the lockfile.

A mature numerical port is preferable here to a newly designed polynomial approximation or adding a WebAssembly build toolchain. Cost acceptance still requires measuring bundle increase, replay/host CPU and frame time. Keep numerical compatibility identifiers current and retain both original mismatch traces. Apply the helper at all simulation-relevant trigonometry sites, including the shared movement kernel and gun steering; isolated cosmetic rendering math need not become authoritative.

Test zero axes, negative zero, quadrants, range-reduction boundaries and representative in-game angles across Node/Chromium/WebKit, followed by the complete match and checkpoint-suffix tests. The selected `atan2` explicitly observes sign bits, while ordinary JSON serialization and the initial canonical serializer collapse `-0`: prove a simulation invariant that this cannot affect continuation, normalize consistently at the shared numeric boundary, or preserve signed zero in both checkpoint and hash representations. Do not let an apparently matching canonical hash conceal a continuation-relevant signed-zero difference. These conditions approve the next implementation step; they do not certify the installed library graph, bundle, revised physics or engine acceptance before inspection and completed tests.
