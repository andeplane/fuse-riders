# Fuse Birds ADR review — 2026-09-22

Scope: ADRs 048–051 and their concept specification. Documentation review and corrections only; no game, renderer, assets or performance harness was implemented. The user has accepted the V2 graphics and requires a UI-independent headless game library.

Subsequent scope update: [ADR-052](../adr/052-fuse-birds-phase-one.md) narrows Phase 1 to unlimited Pebble, three starting Scatter Bombs with a visible count, ammo-refill crates and one finished V2 theme. This review remains the record of architectural findings; its mentions of medkits/shields and five-theme validation apply only when those later features are implemented.

## Findings and corrections

| Finding                                                                                                                              | Correction                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rendering described textures and glow but did not explain how to reproduce the detailed V2 art                                       | ADR-051 now specifies authored rock/character/scenery assets, world-space material composition, occupancy clipping, regenerated bevel/rim lighting, anchored decoration, water layers and a real-renderer visual acceptance slice                                                                  |
| A generic terrain-mask implementation could assume Phaser 3/WebGL APIs that are not supported by the pinned renderer                 | Select independently implemented CanvasTexture composition with baked alpha, based on current repository code. Document Phaser 4 mask limitations, whole-chunk uploads and the optional Extern path. The installed primary-checkout Phaser 3.90.0 is stale relative to the 4.2.1 manifest/lockfile |
| A one-cell chunk halo was too small for the proposed bevels/glow                                                                     | Bound shading support with an initial eight-cell gutter, invalidate every affected neighbor, and draw only each chunk core. Add concrete CPU/GPU texture-memory accounting                                                                                                                         |
| Launch validation mentioned speed but not membership in the generator's discrete legal launch set                                    | Require exact launch-table membership and checked-in versioned integer tables                                                                                                                                                                                                                      |
| A direct hit could be counted twice or do no damage depending on blast sampling                                                      | Specify per-explosion maximum of contact and exposed blast damage, direct crate collection, and separate contributions from separate explosions                                                                                                                                                    |
| Mutating a step before an internal work-budget failure could leave corrupt partial state                                             | Compute bounded changes before commit; return a fault with healthy state intact and do not assume recovery fixes a reproducible rule fault                                                                                                                                                         |
| Movement during aiming, pass while falling and walking up raster steps were underspecified                                           | Advance movement physics while aiming, settle after pass/expiry/death, and use a bounded step-up/hop/support rule                                                                                                                                                                                  |
| Reward ordering mixed projectile damage with later falling damage                                                                    | Specify projectile damage/death, crate rewards, terrain changes, then body/fall/hazard effects; newly collected effects cannot undo earlier damage                                                                                                                                                 |
| Parachute crates in the accepted art were not shootable under the previous scheduled-delivery proposal                               | Make the descent part of the engine with an interactive collider; passive crates do not block turns or results                                                                                                                                                                                     |
| Crate candidate searches and draws could extend resolution indefinitely                                                              | Bound/checkpoint crate searches, skip failed drops, bound consecutive draws, and explicitly advance sudden-death water in the engine                                                                                                                                                               |
| A reachability candidate could implicitly reuse the previous candidate's crater                                                      | Require isolated scratch simulations from identical starting state and replayable successful witnesses                                                                                                                                                                                             |
| Unlimited ammunition and a small automatic roof-clearing mask were presented as stronger reachability guarantees than they establish | Remove free roof excavation; distinguish verified opening shots, world-range coverage and later trapped-position escape. Require explicit counterexamples/witnesses and acknowledge that ongoing reachability is unverified until the physics/generation prototype                                 |
| Snapshot cost was described only abstractly                                                                                          | Calculate packed terrain size against the actual 12-snapshot retention and 2,000,000-byte transfer cap; prohibit retaining a full grid per search candidate                                                                                                                                        |
| The concept spec still asked the user to select an art direction and delayed every crate reward to next turn                         | Record V2 as accepted, five themes of one game, align bird scale and distinguish immediate defensive/health effects from next-turn ammo                                                                                                                                                            |

## Remaining implementation evidence

The design now names concrete mechanisms and acceptance checks, but it does not prove a working product. The first implementation slices must establish:

1. Identical complete-match hashes in headless Node and browsers, including movement, checkpoint recovery and interrupted input.
2. Baseline shot range and legal opening witnesses, plus counterexample-driven tests of later trapped positions. Ongoing all-position reachability remains a requirement to establish, not a shipped guarantee.
3. Generation latency, snapshot size and clone cost with bounded preparation scratch.
4. A real textured renderer matching V2 at full-map and phone-close-up scales, including new crater edges, broken decorations, rollback and context restoration.
5. Actual phone frame-time/memory and TV readability measurements. The arithmetic budgets in the ADRs are estimates, not measurements.

All ADRs remain Proposed. User acceptance of the art does not imply acceptance of unseen gameplay feel or authorization to implement, merge or deploy from this documentation review.
