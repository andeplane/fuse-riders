## Reproduced engine findings

1. **P1: destroyed priorities remain permanently allocated.** `engine/index.ts`, priority command handling, requires an owned structure even to clear a priority. Destroy eight prioritized structures and the player cannot clear those entries or allocate a ninth destination. Allow clearing a stale entry and/or remove priorities on destruction. Cover destruction followed by reallocation in a regression.
2. **P1: malformed checkpoints pass decoding and fail on the next tick.** Removing `settings` is masked by the default argument of `createMatch` inside validation, but the original invalid world is returned. A subsequent construction command throws. Empty `statistics: {}` is also accepted, then income produces `NaN`. Validate presence and every required numeric counter explicitly before returning any decoded state.
3. **P2: same-tick construction contention is biased by player ID.** Brains at cells 9 and 11 both enqueue cell 10: lexicographically first player reserves it and pays. The other waits. Collect simultaneous eligible claims before applying an explicitly fair deterministic tie policy; changing input array order alone cannot fix ID ordering.
4. **P2: builders cross severed edges.** Builder travels 10→11; destroy 10 while 11 remains connected by another path. Current worker code completes that edge and builds instead of recovering. Validate both edge endpoints throughout transit, including arrival ticks.

The existing 12 engine tests passed despite these failures. The 128-unit relay buffer versus 32 deployed quota is intentional, not a capacity defect. Current implementation requires all six supporting cells for tower firing; older gameplay wording must be reconciled rather than treated as an authoritative contrary rule.

## Reproduced adapter findings

1. **P1: spectator checkpoint roundtrip fails.** Shared management creates watcher seats with `avatarId: ""`; Neural Defence's decoder rejects them. A valid room containing a watcher cannot restore its own checkpoint. Accept the shared watcher representation and test actual management entry → encode → decode → hash agreement.
2. **P1: combat-lab start crashes with two human seats.** `prepareCombatLab` assumes a two-player roster contains `lab-opponent`; the adapter calls it for two human seats too. Enforce the lab's single-human scenario explicitly at settings/start validation and preserve supported multi-owner headless scenarios separately.
3. **P2: sparse spawn slots fail at start.** A valid map with slots 0, 2, 3 and seats 0, 2 is accepted, but start assigns roster slots 0, 1 and throws. Preserve valid explicit seat/spawn assignments and refuse unsupported assignments without changing healthy state.

Inspection of retained/current stream selection found no concrete error in the reviewed generation-selection path. This is not comprehensive replay qualification.
