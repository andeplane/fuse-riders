# ADR044: Short adaptive presentation history for direct simulation

Date: 2026-09-14. Status: design and implementation independently reviewed; local rendered response and regression checks pass. Broader network/device qualification remains. Tracking #82. No release authorization.

## Decision and alternatives

Render remote geometry from a coherent 50–100 ms history of the locally simulated world. Preserve the local rider's existing immediate fractional steering preview. This is presentation only: simulation ticks, collision rules, action timing, finality, transport and LAN/solo remain unchanged. Current forward projection makes newly received remote turns visibly correct; waiting for finality would introduce up to a second of avoidable visual delay. A fixed history helps but does not adapt to varying delivery. Do not add network snapshots or another simulation mode.

The rollback candidate retains the last four exact per-tick `ViewSnapshot`s, created on simulation ticks, including bombs, trails, pickups and portals. Count their encoded bytes in the existing 32 MB retained-world ceiling. Candidate construction and rollback reconstruct the history atomically with simulation: preserve frames at or before the restore checkpoint, replay/replace the affected suffix, then retain the newest four. Temporary `stateAt`/finality-proposal replay owns its own map and must never mutate installed history. Snapshot fields must not alias mutable game state; rejected input never changes it. Finality trimming retains these four presentation frames even when older replay checkpoints are removed. A new segment starts a new history. Read-only presentation access never advances or replays physics from a render frame.

For each remote input slot, retain the latest 32 lateness samples from `DirectStream.added` newly executable contiguous actions after the complete world admission commits, using one captured fractional clock reading (local fractional tick at admission minus action tick, floored at zero). Duplicates, receipts, empty heartbeats, invalid packets and local inputs do not add samples. Sampling after gap repair measures when the action can actually influence the reconstructed world. Choose the largest per-slot p95 plus half a tick, clamped to 1–2 ticks. Start at 1.5 ticks; increase delay at up to two ticks per second and decrease at up to a quarter tick per second. Sparse/idle traffic does not expire adverse evidence or fabricate good samples. Replacement aliases reset the samples.

Playback uses the existing fractional simulation clock minus the adaptive delay, bounded by available history and a nondecreasing presentation tick. Interpolate continuous poses and compatible shell motion between adjacent exact frames. Discrete geometry belongs to the older tick: no future trails, pickups or blast objects. Portal transitions, deaths and phase/round changes hold the older raw frame until playback reaches the newer tick, then snap; the existing helper that immediately returns a newer phase must not be reused unchanged. Newly created ordinary trail segments may be extended only to the interpolated rider head, using the exact segment's endpoints and timestamps; never invent a straight chord through a turn or portal.

Overlay finalized outcome fields after raw-history interpolation, so provisional phase/death fields cannot become public. Preserve the existing finalized outcome contract: phase, scores, winner/placements and alive flags remain controlled by finalized state. Confirmed outcomes may bypass the small presentation delay; this change does not delay committed audio/UI or make visual history authoritative. Do not smooth a correction through a collision or keep a confirmed-dead rider alive. Materialize the local trail extension in the supplied snapshot for both Canvas and Phaser; neither renderer may infer it from the delayed global tick. Local preview overlays only the current local rider pose and its own real recent trail, plus the existing bounded fractional cosmetic extension; it must never alter collision state. The rest of the scene stays on the delayed geometry tick. This mixed-time presentation can still expose a late correction near interacting riders; no guarantee of invisible rollback under arbitrary network delay is made.

## Failure behavior, costs and acceptance

If a segment is frozen, unqualified or faulted, retain the existing frozen view. There is no extrapolation of remote entities beyond the newest available frame. History is four snapshots per simulator, zero on controllers, inside the retained-world byte cap. Render work is interpolation over supplied snapshots; it cannot publish actions, finality or effects. Record delay, actual presentation tick, history bytes and correction diagnostics through the existing runtime diagnostics.

Before implementation: independent design review. Before release: implementation review. Tests must cover exact history after on-time vs late/reordered replay, atomic rejection, finality pruning, bounded history, sparse/duplicate sample behavior, delay bounds and monotonic playback, own immediate steering, discrete geometry/portal/death handling and alias reset. Run a browser play/response fixture with real rendering and record input-to-render, frame time and correction distributions; a simulation-only traffic pass is insufficient. Preserve the existing local/regional outcome checks and LAN smoke. Broader physical-device and sustained-network qualification remain explicit.
