# ADR 020: Original synthesized TV audio

Status: Historical, amended by the dated updates below. The original synthesized soundtrack and TV-only policy are superseded: current music uses recorded tracks through `HTMLAudioElement`, while effects remain synthesized. See `src/client/game-audio.ts`, `audio-director.ts` and `radio.ts` for the current implementation.

The opening paragraphs preserve the original decision; later dated updates take precedence.

Use a TV-only Web Audio synthesizer for an original looping arcade melody, bass and percussion. All notes are composed in source; no licensed recordings or external audio requests. Separate music/effects mute controls and volumes remain accessible beside TV controls. Audio starts only after an explicit host gesture; unsupported or blocked audio never blocks play.

A small pure audio director receives typed authoritative server messages and an injected synth/time interface. It scopes event deduplication to match/round, establishes a snapshot baseline after every connection, and discards old events. Simultaneous volley launches/explosions coalesce per tick. Pickup cues use a new authoritative pickupCollected event after successful collection; initial/reconnected snapshots are silent. Review refinement: live snapshots omit statistics until match end, so events avoid additional payload overhead. One bounded scheduler emits music steps while playing/countdown and resets scheduling after inactivity instead of replaying missed notes.

Web Audio adapter owns short oscillator envelopes, limits voice lifetimes, and applies independent channel gains. No audio on phone controllers. Tests inject a recording sink and clock to verify unlock, mute/volume routing, score scheduling, event deduplication, reconnect silence and pickup detection. Browser checks verify controls and gesture activation; physical TV speaker listening remains a user check.

The soundtrack now contains six original compositions: Fuse Riders, Photon Sprint, Bubble Circuit, Midnight Tunnel, Voltage Garden and Comet Carousel. Each has a 512-step / 64-bar arrangement lasting 57–74 seconds with sparse intros, answering melodies, bass movement, counter-arpeggios, breakdowns, fills and octave-lifted climaxes. The playlist advances on each new active round and on arrangement completion; reconnecting does not select the first track again. The Audio panel also offers Next tune. Track changes preserve separate volume and mute settings. Pure score tests cover every step of all six arrangements, section variation, valid notes and bounded voices; director tests cover automatic/manual rotation and round transitions. The existing 32-oscillator global cap and no-catch-up scheduler remain in force.

Update 2026-09-15: the synthesized score is replaced by recorded tracks in `public/music/`, listed in `MUSIC_TRACKS` in `src/client/audio-director.ts`. The Web Audio adapter fetches and decodes the current track into the music gain channel, so mute/volume behave as before. Effects stay synthesized.

Update 2026-09-15 (background music): the soundtrack is background music that plays continuously for as long as the page is open. Rounds are short and the tracks are not, so nothing about the game state may restart a track.

- The playlist advances only when a track finishes or someone presses Next tune. The earlier rule that advanced it on each new active round restarted the recording every round and is removed; round, match and rematch transitions leave the current track alone. `AudioDirector.playBackground()` starts music with no match attached, so the landing page and a room that has not connected yet both have a soundtrack.
- A hidden tab keeps its music. `visibilitychange` used to call `disconnect()`, so alt-tabbing away and back restarted the track from the top; it now calls `setEffectsSilenced()` instead, which drops effect cues for a room the viewer cannot see while the track plays on. Only `pagehide` stops music.
- Music plays through a plain `HTMLAudioElement`, not the Web Audio graph, so a phone's volume keys reach it and it plays on while iOS suspends the effects context — a decoded buffer routed through an `AudioContext` does neither. (The silent switch is a session category, not an element property; see the 2026-09-15 update below.) This also replaces the whole-track decode, which held roughly 60 MB of PCM per track. Effects stay synthesized on the Web Audio graph, and the music channel's gain is the element's `volume`.
- Browsers refuse audio before a gesture, so the first `pointerdown`, `keydown` or `touchstart` anywhere on the page retries the unlock and starts the track. The Audio panel's enable button remains for a later refusal.
- Mute and volume for both channels persist in `localStorage` under `fuse-riders-audio` through `safeStorage`, so turning music off on the landing page keeps it off through the page load into a room. Corrupt, partial, out-of-range or blocked storage falls back to the defaults.
- The landing page carries a music on/off toggle in its top bar, in the same position as a room's `♫ AUDIO` button; both are wired to the same persisted state. (Superseded 2026-09-15: every page now carries the same **♫ MUSIC ON / OFF** toggle next to **♫ RADIO**; see below.)

`tests/audio-director.test.ts` covers the round/match transitions, the hidden tab, the refused unlock and background playback; `tests/game-audio-settings.test.ts` covers the stored settings. `scripts/landing-music-smoke.ts` drives a real browser over the landing page: music playing with no room, the toggle's position and touch target, alt-tab not rewinding the track, and the setting surviving a reload. `scripts/online-smoke.ts` checks that CREATE ROOM keeps the document and the same media element, since a page load would cost the soundtrack until the new page is tapped.

Update 2026-09-15 (Fuse Riders Radio, #112): the listener controls the music on top of the background-music rules above.

- `src/client/radio.ts` owns the listening state — track, position, pause, loop song, loop playlist, all-tracks or playlist source, and one playlist — persisted under `fuse-riders-radio-v1`, next to the unchanged mute/volume record. Stored fields are validated one by one; a corrupt field takes its default. Its pure queue rules: a finished song repeats with loop song, a finished playlist stops unless loop playlist is on, all tracks always wrap, Next always wraps, and Previous restarts a song more than three seconds in.
- Every page is a full load, so "the song keeps playing" between the landing page, rooms and the TV is a resume: the position is saved every two seconds, on a hidden tab and on `pagehide`, and the next page seeks the media element there once its metadata loads. Expect a short gap while the next page starts, not gapless playback; a resume point past the end advances to the next track.
- The **♫ RADIO** panel replaces the Audio panel: an LCD with title, track number, time and loop/source flags; previous, play-pause and next; source and loop switches; the mixer; the track list and playlist. Pause stops the element and keeps the position; mute behaves as before. Ctrl+A toggles the radio, Ctrl+M mutes both channels (or unmutes both when both are muted), Ctrl+Alt+M and Ctrl+Alt+E mute one channel. Shortcuts use physical key codes, run in the capture phase and leave text fields' own Ctrl+A alone.
- `src/client/radio-media-session.ts` mirrors the radio onto the Media Session API (#135): metadata (title, artist _Fuse Riders Radio_, album, `public/radio-artwork.png`), playback state (playing only when unlocked, unpaused and unmuted), position state while the length is known, and `play`/`pause`/`previoustrack`/`nexttrack` handlers that call the director's own actions so loop song, the playlist and the saved position apply from a lock screen or a car as from the panel. A typed port keeps it unit-tested; without the API nothing is bound. "Playing" is the media element's own state, not the effects AudioContext (iOS suspends that on lock while music plays on). Pause and play events the synth did not start — headphones out, another app, a car's stop button — are followed by the radio (`mediaPaused`/`mediaResumed`), which disarms a paused track so a later tap on the page cannot restart it. The last known track length is kept while paused so scrubbers do not reset; `playbackRate` stays 1 because the API rejects 0, and `playbackState` stops the extrapolation.

Update 2026-09-15 (iPhone silent switch and the first tap):

- iOS mutes only an _ambient_ audio session with the silent switch; a page with a playing media element gets a _playback_ session by default, which ignores the switch — so the earlier claim that the media element made the switch work was wrong, and effects on the Web Audio graph inherited the playback session while the element played. `requestAmbientAudio()` in `src/client/game-audio.ts` sets `navigator.audioSession.type = 'ambient'` (WebKit's Audio Session API, Safari 17) wherever the API exists. The cost is that ambient audio stops when the screen locks, so the lock-screen and CarPlay controls from #135 only play the radio while the phone is awake; the switch was judged the more basic expectation for a game.
- The director hands the track to the synth as soon as something wants music, before any unlock. It used to wait for a successful unlock, so on a phone the first tap only unlocked (the synth had no track to play inside the gesture) and a second tap — in practice toggling music off and on — was needed. The synth already retried a refused track on every gesture; it just had nothing to retry.
- The **♫ MUSIC ON / OFF** toggle now labels what is audible, not the stored setting: an untapped page, a paused radio and a muted channel all read OFF, and tapping OFF unmutes, unpauses and unlocks inside that gesture. The room header and the TV toolbar carry the same toggle next to their **♫ RADIO** button, so every page uses the same two controls with the same words; the phone landing page no longer abbreviates RADIO to an FM badge.
- Two consequences accepted with that: an unmuted desktop page now sets the element's `src` at load (preload) rather than on the first gesture, so a bounce visitor may download a track; and an ambient session means a screen lock pauses the element like headphones-out does, which `mediaPaused` records as a paused radio, so after unlocking the phone the toggle reads OFF and a tap on it (not just anywhere) resumes the song.
- `loadAudioSettings(storage, musicOffByDefault)`: on touch-first devices (`(hover: none) and (pointer: coarse)`) music starts off on the first visit, because nothing can play there before a tap anyway; a stored choice wins either way, and every page is a full load so the same default applies on each until the listener chooses.
