# ADR 040: deterministic action replication prototype

Date: 2026-09-14. Status: approved for bounded implementation after independent design review and the amendments below; no release approval. Issue: [#82](https://github.com/andeplane/fuse-riders/issues/82). Design input: [brief](../online/DETERMINISTIC-ACTION-LOG-BRIEF.md). Review: [independent findings](../reviews/action-log-design-review.md).

## Scope and alternatives

Implement an opt-in online prototype (`replication=actions`) on an isolated branch. Preserve the existing default snapshot path, LAN authority, rendering and backend. This milestone must actually run browser rooms from replayed accepted inputs, expose reproducible replay/checkpoint tests and measure bytes. It is not a public release or certification of physical phones. Do not claim completion of full-world speculative rollback, mesh agreement or cross-browser numerical guarantees not established by tests.

Alternatives are optimized binary snapshots (lower implementation risk, continued geometry traffic), full mesh input rollback (requires peer agreement on finality/disconnects), and input-delayed lockstep (slow participant can stall everyone). Choose the existing lease-fenced host as input coordinator and reliable ordered WebRTC initially. This isolates simulation correctness from a new unreliable input protocol. Loss/reordering at the application boundary still requires safe detection/recovery; a later unreliable transport needs its own measured decision.

## Authority, time and action boundary

Keep 20 Hz and the current intended/applied tick scheduler, ten-tick held-control timeout, separate ordered bomb transitions, no stale fire replay and host-local management. Record the exact resolved controls and ordered bomb commands immediately before the shared game step, including host-generated bot inputs and timeout cancellation. Store held control changes; unchanged held state persists and transient bomb commands never persist. Record every non-step game mutation (join, remove, connection, avatar, active settings, start/next round/reset) through the same shared reducer. Admission queues, credentials, socket/clock state and local storage stay outside it.

The shared replay layer applies a complete tick transaction and emits existing snapshots/events. A frame identifies its committed tick and stream sequence, including progress with no input changes. Per-player controls are numeric-slot tuples, with a batch tick anchor and delta tick; ordering across players is the deterministic game step's responsibility. Same-player bomb transitions retain sequence. Lifecycle records have explicit order relative to step boundaries. Runtime publication may batch several records; it never silently skips an intermediate record. New match/authority/connection/replica generation fences old data.

The journal operation sequence is independent of game.tick: several lifecycle mutations can occur at one tick. A publish transaction covers all pre-step lifecycle changes, resolved inputs and ordered bomb commands, shared step, then post-step cleanup/next-round mutations. Hash and publish only the complete transaction. Live replica-derived events are suppressed; existing scoped authoritative event delivery remains the only audio/effect event source. Offline replay may return derived events for comparisons.

The first live prototype retains current local movement prediction and confirmed remote interpolation, fed from the reconstructed full snapshot. It does not introduce speculative remote deaths/scores. Full-world rollback is a follow-on, after replica determinism/replay costs are established. Guest-to-host input retains the current scheduler and freshness semantics initially (including 50 ms held-state refresh); replacing this with edge-only input is separately gated on explicit gesture receipts and freshness repair. These limits must be visible in the implementation report, not hidden behind the action-traffic estimate.

## Wire protocol and roles

Use pinned `@msgpack/msgpack`, arrays for hot records, binary WebRTC messages and bounded runtime validators. Prototype capability handshake includes version and full-view/controller role; negotiate before sending binary replay traffic. Old clients continue on the existing path unless they explicitly requested the incompatible prototype, which must fail visibly. Transport-level incarnation/epoch/sender/receiver checks remain mandatory for binary envelopes.

Full-view peers bootstrap from a complete validated game/held-input checkpoint, then consume accepted action batches. Controller-only peers receive compact status snapshots with no trails/projectiles or simulation state, retaining roster, cooldown, charge, effect, outcome and targeting UI needs. Host always simulates; separate TV and individual views simulate; guest controllers never instantiate a replica. A mode/role change forces a new stream baseline. Prototype links/invites must preserve the requested mode.

The host keeps a bounded record ring (at most 400 ticks/records initially), with increasing generation and sequence. Each peer acknowledges accepted progress. Retransmit from acknowledged progress, deduplicate at the receiver, and request a checkpoint when a gap is outside retention or data is invalid. Receiver limits: at most 100 records per message and at most 100 replayed ticks per processing call; larger catch-up uses a fresh checkpoint. Resync max 2/sec. No unbounded out-of-order queues. Pause on missing history and preserve healthy state atomically on invalid candidate input.

Also cap the ring at 2 MB encoded and 20 seconds of simulation ticks, retaining whichever bound is smaller; a batch is at most 128 KB encoded. Validate decoded collection sizes and tuple shapes before cloning/replay. Check state hashes every 20 simulation ticks (and on baseline installation), bound to exact operation sequence. Three mismatches within 30 seconds stop the experimental receiver with a reload/resync explanation; isolated mismatches recover by checkpoint. Recovery leaves the last healthy state intact. Backpressure/retention expiry always creates a fresh baseline, never removes a dependency inside an accepted batch.

Freeze a replay-rules identifier separately from the MessagePack wire version; mismatch requires reload. Preserve semantic Map insertion order in checkpoint serialization/hashing. Bound MessagePack decoder string/binary/array/map lengths as well as outer packet bytes. Pump at most four checkpoint chunks per publish. Add new online protocol modules to enforced coverage; existing thresholds remain unchanged.

Checkpoint transfer is chunked (<=12 KB payload per chunk), capped at 2 MB assembled and one assembly per peer, with a five-second deadline and monotonically fenced transfer generation. Receipt means validated installation, never just successful send. Backpressure respects existing byte gates; checkpoint pumping is bounded per publish. No host bearer tokens or admission state are serialized. Stale chunks cannot supersede an installed generation.

## Determinism and recovery

Add canonical game/held-state serialization and hashes, using the complete simulation state (RNG, counters, portals, stats, timers included), excluding presentation and transport state. Checkpoints validate without the host-refresh sanitizer that disconnects humans and cancels charge. Canonical hashes are consistency diagnostics, not authentication. Compare at fixed committed points, including every tested tick offline and periodic live progress. Mismatch visibly requests a new baseline; repeated mismatches stop the experimental stream rather than silently displaying divergent results.

Exact replay exposed native `Math.hypot` and trigonometry differences between Chromium and WebKit. The independently reviewed numeric amendment uses shared `hypot2(x,y) = Math.sqrt(x*x+y*y)` for bounded finite arena coordinates and pinned stdlib JavaScript sin/cos/atan2 implementations via explicit JavaScript entry points. All shared authority, replay, bot and motion-kernel consumers use the same helper; there is no experimental/default physics split. This changes low-order numeric bits, so checkpoint compatibility is `fuse-simulation-2` and replay rules are `fuse-actions-2`; incompatible saved games require a fresh lobby. Checkpoint serialization and canonical hashing preserve signed zero, including zero-axis headings. Native floating-point arithmetic and correctly rounded square root remain; this is not fixed-point physics.

Audit the bundled dependency graph, retain upstream notices, and compare identical seeded recordings in Node, Chromium and WebKit at every tick, including weapon/portal and checkpoint-suffix cases. Passing sampled traces does not prove all-platform bitwise determinism. Recovery correctness is also tested with deliberately injected hash mismatch.

## Implementation and acceptance

1. Pure action reducer/journal, validated replica checkpoint and MessagePack tuples, with capture integrated in HostSession. Full-match offline replay and checkpoint suffix equivalence; round, settings, disconnect and cancellation regression coverage.
2. Generation/sequence fenced replica and bounded checkpoint transfer. Typed injected transports test lost, duplicated, reordered, corrupt, stale and overflowing messages; state unchanged on rejection; recovery on fresh baseline.
3. Opt-in runtime integration and controller projection. Browser tests prove real WebRTC full view, shared TV/controller roles, mode changes and reconnect in Chromium/WebKit. Record actual accepted replica ticks/hash failures and successfully queued binary payload bytes.
4. Full current suite: both typechecks, unit tests, enforced coverage and production build; LAN smoke; isolated online browser acceptance and sustained five-player-plus-TV exercise. Preserve raw evidence, source identity, seeds and measured scope. Keep physical-phone and real WAN/OS packet-loss acceptance explicitly unverified without hardware/network evidence.

Before public release obtain independent implementation review, complete deployment/release requirements, and decide explicitly whether to enable the new mode. Source stays on the isolated worktree/branch. No paid infrastructure, service simulation, TURN or gameplay relay is introduced. Browser host suspension/availability remains a product limitation. Replay archives are local artifacts, not durable failover.
