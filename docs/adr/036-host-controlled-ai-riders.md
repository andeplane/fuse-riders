# ADR 036: Host-controlled AI riders

Date: 2026-09-14. Status: **superseded** by [docs/online/P2P-INPUT-LOG-BRIEF.md](../online/P2P-INPUT-LOG-BRIEF.md): there is no host session or checkpoint container; AI riders are management entries in the creator's log stream and every replica simulates them (see [AI-RIDERS.md](../online/AI-RIDERS.md)). Originally: accepted for implementation after independent root review on 2026-09-14; implementation/browser acceptance still required. Root also requires LAN exposure as a follow-on within the wider AI feature.

Add deterministic computer opponents to online rooms so a creator can play alone. The host adds/removes bots from the same roster on phone or desktop. Humans and bots share the five-player limit; bots consume no network identity/socket. Bot commands require the host identity. Bots added during a race use the existing next-round admission rule. Removal is immediate in lobby/intermission/match-over; during an active race, explicitly reject with “Remove AI between rounds or return to menu” rather than silently altering the current participants/scoring. UI communicates that limitation.

`src/shared/bot-controller.ts` produces only normal `InputIntent` controls. It cannot move a rider, award pickups, override collisions or launch privileged projectiles. At most three steering candidates and a fixed bounded horizon are evaluated against current visible trails, field boundaries, nearby riders, existing bombs/blasts and pickup positions. It does not inspect human inputs or future random drops. Gun/shell and charged attacks use normal press/release controls and game cooldowns. Ordinary game physics determines every outcome. No claim of competitive/expert play: the initial bot prioritizes survival and opportunistic shots.

Random tie-breaking is injected and deterministic from match seed, bot identity and tick by default; it does not consume the simulation's pickup RNG. Bot planning state is derived from the current game and its authoritative charge field, so restore has no hidden PRNG/charge timeline to replay. Bound work independently of frame rate and record a four-bot/five-rider trail workload measurement.

HostSession owns a private bot registry. Bot IDs use a reserved host-generated namespace for display only; clients cannot claim a bot by setting a player flag. Reject external input/join/avatar commands addressed to registered bot IDs. The registry, rather than a name or prefix alone, determines authority. Snapshot display may recognize the reserved ID for an AI label, while player physics schema remains unchanged.

Extend the reviewed checkpoint container to version 3 with a required bounded unique `botIds` array. IDs must belong to both the validated player map and sequence map, use the reserved bot namespace, and differ from host. Validate everything atomically before commit. Restored humans remain disconnected; validated bots resume connected with neutral charge/input, using the same phase rules. Version 2 is explicitly incompatible under the existing no-implicit-migration policy. Removal also removes registry/seat entries; reset preserves admitted bots.

HostSession injects bot controls immediately before the same `step` call used for people. Network transport/runtime scheduling is unchanged. UI adds ADD AI and per-bot REMOVE AI controls, preserving click target DOM stability across snapshots. LAN uses the same controller in its existing authoritative server, with a host-authenticated hostBot command and TV ADD AI/roster removal controls. Bot seats and human sockets are counted together; a bot is never a fake network connection. The server adds bot controls to its existing step call, preserving its human input scheduler.

Acceptance: deterministic decisions and unchanged source state; steering away from imminent wall/trail/head hazards; neutral dead/waiting riders; normal bomb charging/cooldown/projectile behavior; host-only admission/removal; five total slots; solo host plus bot starts; mid-race joins wait; reset/next round retain correct bot ownership; malformed/duplicate/unknown checkpoint bot IDs reject without mutation; restored humans cannot become bots. Browser verifies desktop/phone ADD AI, solo start, roster removal and a real match with normal scoring. Fixed-work timing report distinguishes measured controller overhead from rendering and network tests.
