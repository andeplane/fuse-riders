# Online release roadmap

> **Status (2026-09-16): superseded.** The "implemented foundations" below describe the host-star runtime that [P2P-INPUT-LOG-BRIEF.md](P2P-INPUT-LOG-BRIEF.md) replaced (every device simulates from one shared input log over a WebRTC mesh; no browser authority, leases only fence duplicate creator tabs, no local checkpoints, no input ledger or world deltas). The remaining gates (physical-device and WAN qualification, sustained active-rider runs) still apply; the brief's §14 lists the follow-ups the new design enables.

Updated 2026-09-14. LAN remains available while the online release is qualified. This roadmap replaces historical PLAN.md. Implementation, successful local checks and verified public deployment are distinct milestones.

## Implemented foundations

The reviewed direction uses a browser authority, direct WebRTC gameplay and a signalling/coordination backend. [ADR 035](../adr/035-direct-gameplay-only.md) explicitly supersedes earlier WSS gameplay-relay fallback requirements. The selected deployment is GitHub Pages plus GCP Cloud Run, Firestore and Pub/Sub; local development and CI run the same room service code over in-memory rooms.

| Area | Implemented behavior | Remaining acceptance |

## Completed evidence and remaining release work

Public product checks, the 30-minute source-66f67bd soak, mobile-sized Phaser benchmarks and subsequent regional/poor profiles are complete within their recorded scopes. See [current release status](PUBLIC-BETA-2026-09-14.md) and [completion audit](../reviews/online-completion-audit.md). The fixed response batch passes both local and TV candidate targets, with prior failures retained. The final tuned runtime 6c1673b passed CI 34796940787, Pages 34797212683 and clean public Chrome/WebKit verification and remains the last runtime with a clean public acceptance record. The restored UI runtime 68bea0d (merged PRs #1/#2: restored neon lobby, landscape touch thirds, keyboard controls, ADR039 short codes) was published by manual Pages run 34819458582 with `sourceVerification.mode=local`: it passed the operator's local suite and Chrome/WebKit checks, its CI run 34819425266 then failed at the "Desktop keyboard steering and firing" browser step after the earlier steps passed. PRs #9 and #11 fixed that step and CI run 34822503284 passed at `a4bee00`, which the automatic Pages run 34823487982 published, so the current public runtime is `a4bee00` with `sourceVerification.mode=ci`; no public acceptance run for the restored UI (either revision) is recorded; see [restored UI release](PUBLIC-BETA-2026-09-14.md#restored-ui-release-68bea0d). Open follow-ups are [issue #3](https://github.com/andeplane/fuse-riders/issues/3) (rich end-of-match stats, podium and awards), [issue #4](https://github.com/andeplane/fuse-riders/issues/4) (landscape controls and menus on physical phones) and [issue #5](https://github.com/andeplane/fuse-riders/issues/5) (real Wi-Fi/WAN latency and phone lifecycle recovery). Poor-profile correction tails are measured and remain a limitation. The checklist below is the release procedure, not a claim that every item has never been run.

1. Run the complete current-revision suite: type checks, tests, enforced coverage, build, Chrome/WebKit LAN and online smoke, AI and Phaser lifecycle/base-path checks. Record exact commit and completed CI result.
2. Run sustained five-player plus TV scenarios with seeded latency, jitter, application loss/reordering, constrained queues and direct-link blackholes. Assert accepted application state and input results, not only packets seen by the harness. Preserve seeds, raw samples, percentiles/maxima and build identity.
3. Measure ADR 032 latency/correction/frame/recovery budgets. Separate payload bytes from wire bytes; keep real packet impairment, phone lifecycle, physical-device and WAN evidence separate. If a gate fails, fix it or obtain an explicit reviewed scope decision rather than silently changing the target.
4. Verify the preview artifact, service resources, IAM and operational limits, then the actual GCP and Pages destinations. Publish the Play link only after the frontend connects to the verified backend. Record service/image/frontend identity and rollback compatibility.
5. Complete independent implementation/release review and align README, ADR statuses, deployment inventory and evidence with the resulting qualified scope. A trusted foreground host and direct-connect NAT limitations remain product constraints.
