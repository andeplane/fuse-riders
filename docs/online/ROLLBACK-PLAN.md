# Rollback netcode: plan for restructuring the stacked PRs

Date: 2026-09-15. Status: **superseded**. The host-anchored rollback stack this plan sequenced was replaced by the peer-to-peer mesh cutover in [P2P-INPUT-LOG-BRIEF.md](P2P-INPUT-LOG-BRIEF.md) (branch `p2p`), which removed `runtime.ts`, `host-session.ts`, `wire.ts`, `action-log.ts` and the controller-phone status path. Kept for the review history. Original status: revised after three independent reviews (netcode correctness, git mechanics, simplicity); awaiting the user's go-ahead before any branch is rewritten. Reference: the user's brief `Fuse Riders Netcode Brief` (peer-to-peer input log). This plan keeps the host as time authority and relay and does not build the peer mesh.

## 0. Why the current stack failed on the LAN

Two mechanisms in today's PRs manufacture the symptoms the user saw. `HostSession.clear()` mints a new control scope for every seat on every phase change, host action and tab hide; a guest learns the new scope only from the next ledger update, and every input in that gap is rejected as "scope expired". That is "presses did nothing". And the freshness rule replaces a seat's bomb buffer after one second of silence, so a Wi-Fi burst mid-charge cancels the charge and the release then matches nothing. That is "releases were ignored". Both mechanisms exist only because the host decides when input applies. The fix is to remove that decision, not to tune it.

## 1. Contract

- **Input is a log entry, not a request.** Each member owns one stream identified by `(memberId, connectionId)`; a new connection starts a new stream at seq 1 and receivers ignore the old one. Entries are `[seq, tick, kind, ...args]` with `tick` absolute and non-decreasing. Player kinds: steer flags, aim, press(gestureId), release(gestureId, aim?), cancel(gestureId), avatar. The creator additionally authors management entries: join, leave, presence(connected), settings, action(start/rematch/lobby, newMatchId), bot add/remove. Bots are ordinary streams: the creator runs `BotController` once per tick against its newest state and appends the resulting edges to each bot's stream; replay never re-derives bot input.
- **State at tick T is a pure fold** of the seed and every entry with tick <= T: management entries at T first, then each player's entries at T folded into held controls and ordered bomb commands, then `step`, then the round progression and outside-play charge clearing that `HostSession.advance` does today. Every management entry has a precondition that is a pure function of the folded state (phase, connected count, free slot, player exists); a failing precondition is a deterministic no-op and nothing in the fold throws. Pending settings and match format come from entries, never from a runtime field. Per-stream bomb semantics use one `BombInputBuffer` per stream, moved to `src/shared/`, so LAN and online share one implementation; its four fields are part of the per-stream state.
- **Every full view simulates to its own clock** and applies its own entries on the next local tick with no round trip. An entry for a tick already simulated triggers one rewind per tick: collect the tick's arrivals, rewind once to the newest snapshot at or before the oldest affected tick, replay once. Snapshots are encoded copies of game state plus per-stream state, taken every 4 ticks, 12 retained (48 ticks of cover for a 40-tick window). Rollback is the normal case for every remote entry, roughly one to three ticks deep per RTT; the measurement in the cutover PR budgets for one rewind per tick.
- **No entry is ever dropped for lateness.** The host forwards every entry it receives verbatim to every other full view before applying it, unconditionally. The host applies an entry older than its window at `hostTick - 39` instead of its stamped tick, so it happens late rather than never. A view that receives an entry older than its own window requests a snapshot from the host. The window bounds re-simulation cost; it never filters history. The "release for an unknown gesture fires at minimum charge" heuristic from today's #90 is removed: repair delivers the press instead.
- **Own stamp** is `min(max(floor(clock) + 1, lastOwnTick), floor(clock) + 3)`; `inputDelayTicks` is 0. A receiver holds entries stamped beyond `localTick + 14` in its out-of-order buffer rather than rejecting the packet; only malformed entries reject a packet.
- **Clock.** The host's tick clock is the reference. Its packets carry its tick and send time plus the recipient's echoed send time; a view sets its clock outright from the first sample, then slews at most one tick per second, forward steps allowed when the estimate is more than four ticks ahead, backward steps only after a host silence longer than one second. Controller phones get the same fields in their status heartbeat and run the same clock.
- **Silence.** When the host has heard nothing from a member for 1,000 ms it logs `presence(false)` at its current tick; every view then neutralizes that player and clears its charge deterministically. A stream that resumes gets a new connection and a fresh stream, and the host logs `presence(true)`. Views never stall for a silent player. If the host itself is silent for more than one second, full views freeze and show "Waiting for the host"; when the host returns it restores its saved checkpoint, serves snapshots, and views re-lock to its clock. There is no creator succession: a room whose host is gone for good ends, as today.
- **Events are keyed by content**, `(tick, type, bombId | pickupId | playerId)`, and emitted once; a re-simulation emits only unseen keys and never un-emits. Round and match outcome UI reads local state.
- **Join, reconnect and divergence** reuse today's baseline message: exact game state from the checkpoint encoder plus every stream's per-stream state and retained entries, on the reliable channel. The host's periodic hash is a diagnostic: a mismatch requests a baseline, three in a minute show a persistent "out of sync, reload" notice. Retention is one rule: keep entries with `tick > localTick - 40`, with a decode-time allocation guard as the only count cap.
- **Wire.** One packet per tick per sender on the existing unordered, no-retransmit `fast` channel with today's four-field envelope: `[protocol, roomHash, senderIndex, streams: [[connectionHash, through, lastSeq, entries...]], tick, sentAt, echoSentAt, hash | null]`. Guests send one packet with their own stream; the host sends one packet per recipient per tick carrying every other stream's newest entries plus rotation through retained ones, so every retained entry is resent within about 600 ms with no acknowledgements. A receiver that sees a seq gap sends a nack on the fast lane; the host answers nacks for every stream, since it retains them all. Liveness of other players comes from the host's relay and `presence` entries; echo-derived RTT is used only on the host link. The reliable `game` channel keeps baseline, events, management and thin status. The existing 4 KB decode cap and bounded MessagePack options stay; there is no separate 512-byte cap.
- **Controller phones** send their stream and receive the thin status only when it changes plus a heartbeat every five ticks, as today, with `tick`, `sentAt` and echo added. The phone renders its own press, charge and aim from its local entries immediately and takes only bomb-ready, alive, wins and phase from the status, so its button feedback does not wait for a round trip.
- **Presentation.** Full views render `interpolateWorld` between their last two simulated ticks at the fractional clock. `RemoteWorldBuffer`, `LocalPrediction` and its ledger, tick probes and the shot-failure notice are deleted; there is no "shot not accepted" state because the local view applied the press.

## 3. Tests that gate each PR

- #91: every entry kind validated and folded; second press while a gesture is active yields cancel then press; mismatched release is a no-op; all arrival orders of the same entries converge to one hash; a late entry rewinds N ticks and re-simulation is byte-identical including replayed bot entries; management precondition failure after a rewind is a no-op on six replicas; a rewind across a round boundary replays the transition; event keys survive a rewind that changes which bomb explodes; six replicas on a deterministic fake network with 5 percent loss, 100 ms jitter and reordering agree at every tick and repair every gap within 600 ms; the differential test that the shared `BombInputBuffer` and the fold produce identical command sequences for the same edge series.
- #92, the two cases that reproduce what the user saw, in their words: hold the fire button, lose every packet for 1.5 s, release, and the shot fires; press during a round transition and the press is not lost. Plus the browser smoke in Chromium and WebKit: create, five joins, start, three rounds with bots, guest refresh mid-round, creator refresh mid-round with the checkpoint recovery, settings change, shared-TV with two controller phones. Measurement report: bytes per second each way per peer, rewinds per minute and ticks per rewind, input-to-own-render and input-to-remote-render p50 and p95, on LAN and with 40 ms delay, 20 ms jitter and 2 percent loss.
- #94: status only on change, heartbeat cadence and clock fields, local echo timing.

## 4. Git sequence

1. Commit this plan; tag every current branch head as `stack-v1/<branch>`; push tags.
2. #96: cherry-pick its three commits onto a fresh branch from `main`, retarget the PR to `main`, merge when green.
3. Retarget bases before any force-push, bottom-up: #91 to `main`, #92 to `codex/action-log`, #94 to `codex/action-replication`; close #90 and #93 with a pointer to #91.
4. Rewrite `codex/action-log` from `main`; force-push with lease; rerun CI explicitly, since a base change alone does not trigger it; wait for green.
5. Rewrite `codex/action-replication` on top; force-push; browser smokes green.
6. Rebase `codex/controller-only-phones` by cherry-picking its unique commits onto the new #92 (the branch has merge commits); force-push.
7. Retitle the three PRs and regenerate the stack tables. After each force-push, local checkouts of that branch are reset to origin in their own worktree.

## 5. Risks

- Host uplink: one coalesced packet per recipient per tick, about 100 to 200 bytes, so four guests cost the host under 16 KB/s. Measured in #92.
- Rewind cost on phones: one rewind per tick of one to six ticks depth, measured in #92 before cutover; the ring keeps replay short.
- A stream that goes silent mid-charge holds its charge until `presence(false)` at one second, then loses it, instead of today's freshness reset. Deliberate.
- Visible corrections of other riders on late entries; an adaptive remote presentation delay is added only if measured corrections are visible on Wi-Fi.
- Creator refresh keeps today's checkpoint recovery and pause semantics; there is no failover.
