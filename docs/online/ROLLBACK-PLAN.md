# Rollback netcode: plan for restructuring the stacked PRs

Date: 2026-09-15. Status: draft for review. Replaces the "host admission window" contract of PRs #90 and #92 with input entries applied at their intended tick on every simulator, with rewind and replay when an entry arrives late. Reference design: `docs/online/P2P-INPUT-LOG-BRIEF.md` (the user's brief). This plan keeps the host as time authority and single relay; it does not build the peer mesh.

## 1. Contract

- **Input is a log entry, not a request.** Each player owns one stream of entries `[seq, tick, kind, ...args]` with `tick` absolute and non-decreasing. Kinds: steer flags, aim, press(gestureId), release(gestureId, aim?), cancel(gestureId). The creator additionally owns management entries: join, leave, presence, settings, action(start/rematch/lobby), bot add/remove, avatar.
- **State at tick T is a pure fold** of the seed and every entry with tick <= T. There is no admission window, no applied/superseded/expired result, no freshness expiry on the host; a stream that goes silent keeps its last held controls until the creator logs `presence(false)`, which neutralizes it.
- **Every full view simulates to its own clock** (host, personal devices, TV). A player's own entry is applied on the next local tick with no round trip. An entry that arrives for a tick already simulated triggers rewind to the newest snapshot at or before that tick and re-simulation to the present. Rollback window: 40 ticks; snapshot every 4 ticks, 12 retained (from the brief). Entries older than the window are dropped; the sender never learns, which is acceptable for a party game.
- **The host is the time authority and relay.** Its tick clock is the reference; its per-tick packet carries its tick and send time, and every view estimates one offset and slews at most one tick per second. Guests send entries to the host; the host forwards each stream's entries to every other full view and produces the thin status for controller phones. Other players' entries reach a view one hop later than in a mesh; own entries have zero hops.
- **Bounded stall.** If a connected stream is more than 40 ticks behind the local tick, the view keeps simulating with predicted held controls; the host logs `presence(false)` after 1,000 ms of silence, at which point every view neutralizes that player deterministically. Nothing waits for a certificate, acknowledgement or barrier.
- **Events are emitted once** per (tick, index) key; a re-simulation emits only keys not yet emitted and never un-emits.
- **Join, reconnect, divergence** use a snapshot: exact game state (existing checkpoint encoder) plus each stream's held controls, active gesture and retained recent entries, in <= 16 KB chunks on the reliable channel. A periodic hash from the host is a diagnostic only: mismatch requests a snapshot, three in a minute show a persistent notice.

## 3. Git mechanics

Branch order today is 90 -> 91 -> 92 -> 93 -> 94 -> 96. New order is 91 -> 90 -> 93 -> 92 -> 94 -> 96, because the rollback core (new #90) needs the shared log (#91) and the packets (#93) are needed before the runtime (#92).

1. Cut a fresh `codex/action-log` from `main`; port the shared math and journal commits from today's branch and add the input log and apply-tick. Force-push; PR #91 base stays `main`.
2. Cut `codex/state-based-input` from the new #91; port the controller-side gesture commits, add rollback core and clock, delete the host admission modules. Force-push; retarget PR #90 base to `codex/action-log`.
3. Cut `codex/compact-unreliable-actions` from the new #90; port the wire codec and fast-channel commits, replace the cadence. Force-push; base `codex/state-based-input`.
4. Cut `codex/action-replication` from the new #93; port the world-codec deletion and benchmark script, add the runtime. Force-push; base `codex/compact-unreliable-actions`.
5. Rebase `codex/controller-only-phones` and `codex/dev-room-api` onto the new chain, resolving the status sender against the rollback core. Force-push.
6. Retitle each PR, regenerate the stack tables, and record the review outcome in this document. The old branch heads are kept as tags `stack-v1/<branch>` for reference until the user merges.

Every step ends with typecheck, the unit suite and the coverage gate green on that branch; the runtime PR additionally runs the browser smoke in Chromium and WebKit.

## 4. Risks and open questions

- **Host CPU.** The host now re-simulates on late guest input. Bound: 40 ticks of a five-rider world is well under a millisecond in Node; browser cost to be measured in the runtime PR before cutover.
- **Visible corrections.** Other riders snap when their late input lands; with one extra hop through the host the typical lateness is one RTT. Measure input-to-remote-render p95 in the runtime PR; add an adaptive remote presentation delay only if corrections are visible on Wi-Fi.
- **Own-input vs authority disagreement.** A view's own entry can be dropped by the host only if it is older than the window when it arrives; then the view and host diverge until the next hash and snapshot. Acceptable and rare; log it.
- **Round transitions during rollback.** Management entries are ordinary log entries applied at T before player entries, so a rewind across a round boundary replays the transition deterministically. Needs an explicit test.
- **Two host tabs.** The lease still resolves duplicate creator tabs; gameplay no longer consults it per packet.
