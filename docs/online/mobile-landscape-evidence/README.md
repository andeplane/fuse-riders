# Landscape phone gameplay

Reviewed scope: a joined phone uses one controller presentation in every phase (joined lobby, countdown, playing, roundOver, matchOver): a portrait rotate gate, full viewport landscape arena with `object-fit: contain`, three equal screen-width hit areas, the phase notice floating at the top and the roster plus host actions behind ☰ MENU (#13). `mobile-phase-smoke.ts` screenshots lobby, countdown, playing and matchOver on an 844×390 touch context (`mobile-phase-<phase>-<browser>.png`, `mobile-phase-menu-<browser>.png` / `mobile-phase-lobby-menu-<browser>.png` with the host overlay auto-opened at matchOver / lobby) and asserts the same seven control elements, geometry and labels in each phase; `phase-controls-passing.json` is its output. Solo/device views fade the instruction overlay after three seconds while hit areas remain active. Shared-TV controllers retain player-color panels and persistent instructions with no duplicate arena. The compact menu remains accessible in portrait and landscape; opening tools or rotating cancels held input, without pausing shared simulation. Fullscreen/orientation APIs are attempted only from the explicit button gesture and may be unsupported.

`mobile-landscape-smoke.ts` exercises real Chromium/WebKit browser interaction: exact thirds geometry, contain sizing, faded instructions, rotation cancellation, portrait menu/head/reset access, and (#14) a ≥600 ms long press on each third (CDP touch in Chromium, pointer hold in WebKit) that must leave `document.getSelection()` empty while zones, hint labels, the rotate gate and the MENU pill carry `user-select`, `-webkit-user-select`, `touch-action` and `-webkit-touch-callout: none`; hint labels are CSS generated content with no text node. The initial WebKit failure is retained: its mobile context reports zero maxTouchPoints despite coarse primary pointer. Detection now accepts either capability; the corrected run passes both engines. These are desktop mobile-browser contexts, not a claim of physical iOS fullscreen/orientation-lock support.
