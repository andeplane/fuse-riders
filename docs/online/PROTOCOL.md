# Online protocol contract v2 (proposed review amendment)

> **Status (2026-09-15): superseded for gameplay.** Online rooms now run the peer-to-peer input log recorded in [ADR 047](../adr/047-p2p-input-log-lockstep-rollback.md) (history and measurements in [P2P-INPUT-LOG-BRIEF.md](P2P-INPUT-LOG-BRIEF.md)): every device simulates locally from one shared log over a full WebRTC mesh, with one MessagePack packet per tick per link, rollback, and snapshots from any peer. The host-star sections below (the lease as gameplay authority, the input schedule and ledger, gesture receipts, world replication with keyframes and deltas) are historical. The service parts still apply: room codes and membership, the lease that fences duplicate creator tabs, the signalling payload boundary, STUN-only ICE, link restarts, link diagnostics and the NAT limits.

This appendix makes ADRs 028–032 concrete. It is a design contract, not a claim that v1 prototype packets implement it. One owner integrates the protocol. No authority, receiver or gesture counters are inferred from arrival order. All integer fields below are safe nonnegative integers; runtime validation is mandatory.

## Authority and connection scope

Service state: `{ incarnation: random128, epoch, holderConnection, grantId, validFromMs, expiresAtMs }`. Room initialization creates a new incarnation. Each authenticated socket receives a fresh random connection ID; peer identity is stable separately. Service operations serialize grant allocation/renewal. A renewal names exact incarnation/epoch/grantId/holderConnection and only succeeds if still current and not expired. An obsolete renewal cannot extend a grant.

Lease duration 10 seconds; the creator renews with every `time` heartbeat, every 2 seconds (`PeerTransport.connect`). Replacement reserves epoch+1 but validFrom is no earlier than previous expiresAt plus 250 ms uncertainty guard. It cannot advance or publish accepted state before validFrom. A replacement never renews the old grant. Delayed socket close only affects that socket connection ID. Peers learn grant/connection identities directly from authenticated WSS, not host assertions. A reserved replacement is not an active grant.

Clock mapping uses service ping samples with local monotonic send/receive timestamps and service time. Offset interval is bounded by the entire measured RTT; retain valid bounds without assuming symmetric delay. A peer accepts a grant only when the entire estimated service-now interval lies inside [validFrom, expiresAt). If uncertainty exceeds 250 ms, pause until a fresh sample; this is explicit degradation. Use elapsed monotonic time, recheck after suspension and before every simulation step/frame acceptance. A peer missing renewal stops at its older expiry (safe early pause). Signalling partition therefore cannot overlap old and replacement authorized intervals. Browser host is trusted; this prevents accidental split authority, not malicious modified clients.

`Scope = { incarnation, authorityEpoch, receiverConnection, controlEpoch, matchId, round }`. Host and guest reconnect reset controls and allocate a new service connection scope. Within an unchanged scope counters never reset. Scope changes require neutral handshake and baseline; checkpoint rewind is permitted only as an explicit new-authority discontinuity.

## Input schedule and ledger

Snapshot tick T is state AFTER step T. On host step T+1, consume eligible samples received before the step begins. A sample is `{ scope, seq, intendedTick, left, right, aim? }`. intendedTick is floor(estimated host tick)+1. Reject intendedTick < currentTick-4 or > currentTick+4; reject prior scope. Future samples wait for their intended tick, but a queued sample with a lower sequence than an eligible one is eligible in the same step: sequence order dominates intended tick, so a fire edge stamped from a stale clock estimate is never skipped by a later hold sample whose fresher estimate named an earlier tick (#43). Among eligible samples the greatest sequence wins; acknowledge superseded movement samples explicitly. Movement outcomes do not acknowledge fire transitions: eligible bomb edges are independently processed in sequence order within the step. No rewind. Hold last applied controls until nextTick - lastAppliedTick >= 10 without fresh eligible input, then neutralize. A fresh connection starts neutral. Bomb transitions are not movement samples.

Snapshot includes held controls, lastAppliedSeq and lastAppliedTick, plus application results `{seq, result: applied|superseded|expired, appliedTick?}` for pending samples. Retain results for 100 ticks; client acknowledges exact result sequence IDs (at most 128 per acknowledgement; no cumulative highwater) and host resends until ack or scope expiry. Bounded 128 outstanding samples; overflow forces neutral resync, not silent history loss. Host scheduling results are authoritative. Predictor restores snapshot T, retains authoritative held controls and replays its tick-indexed record after T, correcting assignments when results arrive. This includes fully acknowledged held turns. Prediction lead cap is four ticks; uncertainty or stale snapshot freezes advancement, never grows an unbounded backlog. Partial-tick preview is cosmetic. The client never pre-rejects a sample because its clock is uncertain or its snapshot lags (#15): it always sends `floor(estimate)+1` and only the host window decides, so a slow link yields explicit `expired` results rather than certain local loss. A sample the transport refuses is discarded from the client record (#20); records behind the host window are pruned on every accepted snapshot; client overflow at 128 drops the stale backlog and keeps sending. The solo runtime's authority is in-process: `LocalRuntime` stamps every input with the authority's next tick before admission, because a stalled main thread lets the wall-clock extrapolated estimate run ahead of the clamped 100 ms catch-up and the sample would otherwise be refused as future (#43).

Kernel state includes x/y/angle, previous drunk offset, drunk start/end/seed inputs, movement speed/turn rate, tick and known boundary/portal context. Unknown portal/obstacle changes remain explicit authoritative corrections. Test two opposing samples at one tick, future/late samples, missing results, drift, host pause and 300 ms snapshots using real scheduler results.

## Fire and management actions

**Current accepted direct-only scope:** [ADR030 amendment](../adr/030-online-delivery-and-replication.md#reviewed-direct-only-action-amendment-2026-09-14) uses the one ordered reliable RTC channel, scheduled/scoped sequence validation, no replay of old fire edges, ten-tick cancellation watchdog and a persistent notice on known press/release failure. Movement outcomes are not gesture outcomes. The full terminal gesture protocol below is a deferred alternative for guaranteed per-gesture receipts or multiple gameplay carriers, not an implemented direct-only release promise.

### Deferred terminal gesture alternative

A gesture is `{ scope, gestureId, transitionSeq, kind: press|aim|release|cancel, startTick?, releaseTick?, aim? }`. IDs increase within control scope. Each gesture state is absent, charging, applied, cancelled or rejected. Last three are terminal; repeated messages return the identical terminal acknowledgement. Cancel before release terminates; cancel after applied cannot undo a shot. A release received before press produces a minimum-charge shot if legal (no invented charge history). Later press cannot resurrect a terminal gesture. Aim updates never resurrect or fire.

For known press, charge begins at its host application tick. Claimed release/start ticks must lie in the input age/future window, start<=release, and same scope. Charge is bounded by host-observed elapsed ticks and existing game charge cap; client metadata cannot grant extra charge. Invalid metadata is terminal rejected. Cooldown, powerup and alive checks use current authoritative game state. New round/control epoch cancels outstanding gestures.

Retry nonterminal transitions every 150 ms for at most 750 ms; preserve IDs across carriers. No global gap wait: independent gestures/management actions cannot block each other. Retain up to 128 terminal gestures for 5 seconds; rate limit to 20 new gestures/sec. Older wire actions are rejected by tick/scope checks even after eviction. If capacity is exhausted, reject new gestures explicitly until history expires. Management has independent action ID/ack, 3-second retry deadline, 10-second terminal retention and 5/sec limit; validate scope/privileges. Transport retry success is not action success.

## World replication

World identity is `{incarnation,authorityEpoch,receiverConnection}`. Host maintains increasing generation per identity, sequence per generation. Keyframe includes full state, tick, schema version, rules revision, generation and optional resync request ID. Counter reset requires fresh identity. Within identity accepted tick cannot decrease, including keyframes. Validate entire candidate before swapping state/trails/generation. Invalid higher generation cannot retire healthy state. Decoder returns accepted/stale/needsBaseline/invalid.

The former host-star snapshot and replay gates are historical. For the current peer-to-peer snapshot format and compatibility contract, see [ADR 047](../adr/047-p2p-input-log-lockstep-rollback.md). The live compatibility identifier is `RULES` in [`src/shared/apply-tick.ts`](../../src/shared/apply-tick.ts); peers must match it exactly. Both snapshot chunk assembly and decoded snapshot payloads independently reject foreign rules in [`src/online/snapshot.ts`](../../src/online/snapshot.ts). Refresh every peer together when rules change, and start fresh rooms after a rollback.

One resync request in flight per receiver; retry after 500 ms, max 2/sec. Latest request ID binds response; obsolete responses are stale. Encoder generation increments when a stream is replaced or an encoded send cannot be retained. Coalescing applies only before encoding; never drop a delta then encode a dependent successor. On queue overflow terminate generation, discard its pending output and create fresh baseline. Delayed packets from terminated generations cannot supersede the new committed baseline. Periodic keyframe remains in generation and preserves tick order. The shipped direct-only path (ADR030 amendment: one ordered reliable channel) sends no periodic keyframe: only a fresh encoder baselines, since a chained delta stream cannot drift there and a broken chain already resyncs (#61).

## Recovery and evidence

Warm WSS remains available for fallback. Probe direct every 200 ms; three missing application probe acknowledgements triggers fallback, target <=750 ms from first lost probe to fresh input/current baseline acceptance. Probe responses are path-specific (WSS cannot prove RTC healthy). Direct recovery requires two consecutive bidirectional probes plus baseline/application ack, with minimum two-second dwell to prevent flapping. ICE restart uses bounded 1/2/4/8-second backoff. Same-authority recovery after a three-second outage targets <=2 seconds from restored connectivity. Host replacement has a separate bound: remaining lease +250 ms guard +2 seconds handshake; never bypass fencing to meet the path-only budget.

Benchmark cohort is five active riders plus TV for 30 minutes, excluding lobby/countdown from traffic averages and explicitly marking discontinuities. Normal correction profile: 80 ms RTT, 20 ms jitter, 0% loss, alternating steering and held turns, p95 <=7 units; report unknown-obstacle corrections separately, never discard them from the overall report. TV nearby profile: 40 ms RTT, 10 ms jitter, 0% loss. Other ADR 032 impairment/degradation profiles remain required. Version, seed, raw samples, environment and all exclusions are recorded. Preview and public-ready are distinct labels; morning timing does not waive release gates.

## Final review amendments (required for implementation)

Every fire and management transition carries required issuedTick, checked independently against current scope and age before terminal-history lookup or execution. Gesture creationTick is immutable across transitions/retries. Reject future actions rather than executing early; retry can occur when eligible. One charging gesture owns each player at a time; a competing press is explicitly rejected. Expired actions cannot recreate charging state after dedup eviction. Movement result acknowledgement is the highest contiguous resolved sequence, never maximum seen across holes.

Clock uncertainty widens by 1000 ppm elapsed time after each sample (conservative engineering bound), with a maximum sample age of 4 seconds. Sample RTT above 500 ms cannot authorize simulation. Visibility resume, bfcache or detected scheduler gap over 500 ms invalidates clock mapping and requires a fresh service sample. Expiry checks alone do not certify a suspended clock. Bounds and suspension are tested with independent injected service and local clocks. These amendments satisfy the independent design review's remaining conditions; implementation and release reviews remain required. A non-permitted clock pauses advancing, sending and receiving at once; seat control scopes are rotated only after 2.5 s of continuous non-permission (one 2 s sample period plus the 500 ms maximum round trip) or on an actual authority change, so one stalled or uncertain sample does not reset controls (#48).

## Direct link establishment, diagnostics and NAT limits (issues #12, #27)

ICE configuration: `/api/rooms/{code}/ice` (fetched with a 3-second bound; a hung fetch falls back to the defaults) returns STUN only (`stun:stun.cloudflare.com:3478` and `stun:stun.l.google.com:19302`, `relayConfigured:false`). The client validates the list at its boundary and uses the same two STUN servers when the fetch fails or returns nothing; every `RTCPeerConnection` waits for that fetch, so no offer or answer is negotiated without STUN. Signalling carries `{description:{type,sdp}}` or `{candidate:{candidate,sdpMid,sdpMLineIndex,usernameFragment}}` only; one `RoomGateway` applies the `validSignal` boundary in both Cloud Run and the local room service (empty-string end-of-candidates, null fields and mDNS `.local` host candidates pass). Trickle candidates that arrive before their description, while one is being applied, or whose ufrag names a later ICE generation wait in a bounded 64-entry buffer per link and are applied after the matching description; candidates from an earlier generation are parked and never poison the new attempt.

Recovery: the link's initiator (the member with the smaller id; every pair of members has a link in the mesh) issues bounded ICE restarts on the existing connection (`createOffer({iceRestart:true})`, at most four per link, one per eight unhealthy seconds, budget restored by fresh probe health). The answerer recognises a restart by the unchanged DTLS fingerprint and answers on its existing connection; a changed fingerprint means a new connection and replaces the link. A link whose send gate has drained (terminal pc/ICE failure, channel closed, peer retired by the service) cannot be restarted in place because the gate is monotonic; that attempt replaces the RTCPeerConnection and gate instead, carrying the same restart budget. Restart attempts are only issued while the room socket is open. After the budget is exhausted the link stays failed and says so.

Diagnostics: **ROOM → LINK DIAGNOSTICS** shows, per link, local and remote candidate types gathered, the selected candidate pair types, ICE gathering/connection state, peer connection, signalling and data-channel state, DTLS and SCTP state, signalling counts (offers, answers, candidates up/down, applied/buffered/rejected/dropped), restart budget, link age and the last failure name. Chrome stops gathering once a candidate pair connects, so a link that connected quickly on the same network legitimately shows host candidates only; the STUN verdict is only given for links that never connected. No addresses, tokens or invite links appear; the same text is exported as `#app[data-link-diagnostics]` for smoke scripts. The header shows the first missing step instead of a generic retry, for example `no reflexive candidate from STUN`, `signalling never delivered the answer`, or `candidates exchanged, ICE failed — likely symmetric NAT/CGNAT on one side`.

Limitation: ADR035 provisions no TURN relay. When both peers gather server-reflexive candidates and exchange them but ICE still fails, at least one side is behind a symmetric NAT or carrier-grade NAT (common on cellular). Direct WebRTC cannot traverse that combination; the status and this document say so rather than retrying forever. Joining the host's Wi-Fi, or using a network with endpoint-independent NAT, is the only remedy without a relay.

### Power progression (#201)

Fold rules `fuse-p2p-9` introduced the following behavior, retained in rule 11 except for the restored Fuse pickup below. Eliminated riders retain their remaining trails until the next round: elimination sets each surviving segment’s `expiresAtTick` to `Number.MAX_SAFE_INTEGER`, including the final contact segment. This finite deadline survives snapshots and checkpoint validation and keeps bots, collision checks and both renderers using the same obstacle lifetime. Blasts, bullets and closing walls can still cut these trails. Every Power pickup contributes to the diminishing-return weapon curve, replacing the five-pickup level thresholds of rule 7. The curve reaches half its available improvement at 30 pickups; collection does not rewrite existing bombs or running reloads. Power replaces Blast/Fuse pickups: every rider carries required `powerPickups` (round total) and `reloadDurationTicks` (captured at the most recent launch), replacing `blastLevel`/`fuseLevel`. Public snapshots carry both fields; match statistics use `powerPickups` instead of `blastPickups`. Checkpoint validation bounds pickup totals, reload durations and board pickup count using the shared tuning constants. Single-drop scheduling scales with living riders (including bots), and collection remains in seeded fixed-tick simulation, so rollback restores both the pickup total and the active reload exactly. Rule 5/6/7/8 peers cannot join this ruleset; refresh all peers together and use fresh rooms after rollback. There is no conversion of running games. Changes to simulation tuning require another rules bump before mixing builds in online rooms.

### Extra Bomb progression (#208)

Fold rules `fuse-p2p-10` introduced Extra Bomb. Riders and LAN presentation snapshots require `extraBombs`, an integer from 0 through 8. Checkpoint decoding rejects missing, fractional, negative or excessive counts before installation. The pickup type is `extraBomb`; the counter resets with round state and is included in state hashes and peer snapshots. Ordinary volleys use `1 + extraBombs` bombs, plus the existing temporary Triple/Five bonus; special Target/Shell/Cannon launches preserve it. ## Nitro and Snail speed pickups

Fold rules `fuse-p2p-23` introduced Nitro and Snail (#240). Riders, LAN snapshots and checkpoints require two integer lists, `nitroUntilTicks` and `snailUntilTicks`: one absolute deadline per collection, kept ascending, holding at most `MAX_SPEED_EFFECT_STACK` (32) entries each, with spent deadlines dropped at the start of every playing tick so replicas never carry stale ones. Checkpoint decoding rejects a missing list, a non-integer entry, a list past the bound, a list out of ascending order, or a deadline further out than one duration from the checkpoint tick, since the rules never produce those. Nitro appends `tick + 100` to the collector's list; Snail appends `tick + 100` to every other living rider's. `riderSpeedMultiplier` multiplies the boost with 2 per unexpired Nitro and 0.5 per unexpired Snail, and `riderMotionStep` applies the product to distance alone, so steering and collision geometry are unchanged and a Snail cancels a Nitro exactly. Prediction reads the same lists from the snapshot. Bots size their trail horizon from the fastest multiplier any rider can reach inside the lookahead, with the boost as the floor so their horizon is unchanged until a Nitro is in play. The Phaser trail tip and local prediction size their one-step stride bound from the same multiplier. Default spawn weights include both; rule equality rejects older peers and snapshots. Refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

Fold rules `fuse-p2p-24` removed the Boost pickup and rebuilt Gravity. Riders, snapshots and checkpoints no longer carry `boostUntilTick` or `gravityArmed`, bombs no longer carry `gravity`, and `gravity` left the shot log's weapons; `riderSpeedMultiplier` is the Nitro and Snail product alone. Collecting Gravity now opens one to three black holes at once: the count, then a radius in `GRAVITY_MIN_RADIUS`–`GRAVITY_MAX_RADIUS` and a position inside the walls per hole, all drawn from the world's random stream at a fixed three draws per hole. `gravityFields` entries are `{ x, y, radius, expiresAtTick }`, at most `MAX_GRAVITY_FIELDS` (6) with the oldest retired first, lasting `GRAVITY_FIELD_TICKS` (160); checkpoint decoding rejects a radius outside the range, a list past the cap, and an expiry at or before the tick or more than one duration ahead. Each playing tick `gravityBend` turns every living rider's heading before the motion kernel runs, by the share of each hole's pull lying across the heading, scaled by `1 - distance/radius`, summed, clamped, and multiplied by `GRAVITY_BEND` (0.85) of that tick's own steering; position is no longer dragged, so a stride keeps its length. A rider whose swept centre enters a hole's core (`gravityCoreRadius`, 16% of the radius up to 30 units) is eliminated with cause `wall` and no owner unless hazard-immune, and a new hole is slid `GRAVITY_CORE_SPAWN_CLEARANCE` (140) away from any living rider's position for that tick. Bots and local prediction call the same function. Rule equality rejects older peers and snapshots. Refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

Fold rules `fuse-p2p-26` introduced arena maps (#243). Game state, LAN snapshots and checkpoints require `map` (one of `ARENA_MAPS`) and `obstacles`: at most `MAX_OBSTACLES` (40) axis-aligned rectangles with a non-zero integer `id`, a kind from `OBSTACLE_KINDS`, a centre and bounded half extents. `prepareRound` picks the map from the room's `map` setting (`rotate` by round, or a named map; a game with no settings plays `classic`) and lays the obstacles from the game's seeded stream after riders are placed, so the number of samples a round draws now depends on the map. Obstacles kill on contact under the `wall` cause, reflect shells, stop gun rays, are cleared by a blast at its full radius and crushed by the overtime walls; an obstacle a rider or shell already overlaps at the start of its step does not hold it. Room settings gain `map`; a blob without it parses as `rotate`. Rule equality rejects older peers and snapshots. Refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

Fold rules `fuse-p2p-27` added the `wrap` and `cross` arena maps (#248). `cross` folds exactly as `classic` and differs only in presentation. On `wrap` the round starts with `boundaryInset` 0 and the board's edges are open while it stays 0 (`edgesOpen`): committed rider, shell and bomb positions are folded into the board, a trail crossing an edge is stored as separate pieces that end and begin on opposite edges under one `createdTick`, a thrown bomb's `flightPath` stays unwrapped and may run up to one launch distance past the board, and a blast reaching within a rider's radius of an edge is stored as one `blasts` entry per side under the same `bombId`. Gun rays continue from the opposite edge for one board's width of travel in all, each leg a tracer of its own. Overtime grows the inset from 0, which closes the edges; until the inset reaches half a rider's radius the wall's lethal reach is twice the inset rather than the full radius. No state shape changed, so checkpoints validate as before; rule equality rejects older peers and snapshots. Refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

Fold rules `fuse-p2p-28` reshaped the Beer wobble ([ADR 046](../adr/046-drunk-stagger-and-lurch.md)): `drunkHeadingOffset` is a fast side-to-side stagger over a slow aimless lurch, bounded by 45 degrees instead of a 15 degree sine. It remains a pure function of seed, rider, tick and the effect's start and end, and the stored `drunkHeadingOffset` keeps its checkpoint bounds, so no state shape changed; rule equality rejects older peers and snapshots. Refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

Fold rules `fuse-p2p-30` lengthened the pause that ends a match. `matchOver` used to last 60 ticks (plus `REPLAY_PAUSE_TICKS` after a highlight) and every screen named the match winner for all of it, which riders read as the winner of the round they had just watched. It now lasts `ROUND_OVER_TICKS`, plus `REPLAY_PAUSE_TICKS` after a highlight, plus `MATCH_WINNER_TICKS` (60): screens show the final round's own result and replay first, exactly as between rounds, and name the match winner only for the closing `MATCH_WINNER_TICKS` (`showsRoundResult` in `src/client/arena-announcer.ts`). Only `phaseEndsAtTick` moved, so no state shape changed and checkpoints validate as before; rule equality rejects older peers and snapshots. Refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

Fold rules `fuse-p2p-31` (the current rules are `fuse-p2p-32`, see [Deterministic iteration](#deterministic-iteration-fuse-p2p-32)) slow a rider who is aiming. Riders, LAN snapshots and checkpoints require two integers: `aimSlowTicks`, the eased level from 0 to `AIM_SLOW_RAMP_TICKS` (6), and `aimSlowSpentTicks`, the slowdown budget in use from 0 to `AIM_SLOW_MAX_TICKS` (20, one second); checkpoint decoding rejects missing, fractional, negative or larger values of either. A rider is aiming on a tick while `bombChargeStartedTick` is set and the budget is not spent. Each aiming tick moves the level one step toward 6 and spends one tick of budget; any other tick moves the level one step back toward 0, and returns one tick of budget only if no charge is held. Release, cancel and the cap therefore all ease back the same way, a hold buys at most one second of slowdown however long it lasts, and a cancel followed by a fresh press in the same tick buys nothing. Distance is multiplied by a smoothstep from 1 down to `AIM_SLOW_SPEED` (0.5) through the shared `riderMotionStep`, alongside Nitro and Snail, but aiming never takes the combined pickup-and-aim factor below `AIM_SLOW_FLOOR` (0.125, three Snails): self-trail grace is counted in ticks, and a slower rider would die on trail they had just laid. The turn rate is untouched, so an aiming rider turns a tighter circle. A gun fires on the press without charging and never slows. Round reset clears both fields. Bots and local prediction use the same step. Rule equality rejects older peers and snapshots; refresh all peers together, and use fresh rooms after rollback. Room-service and transport envelopes are unchanged.

## Grip steering pickup

Fold rules `fuse-p2p-12` introduced GRIP; `fuse-p2p-13` softened steering from 2× to 1.75×. ### Linear Power trail growth

Fold rules `fuse-p2p-16` introduced the current active-tail tuning. Living riders start with a 160-tick (8-second) trail lifetime, and each Power pickup adds 40 ticks (2 seconds) linearly, up to the 1,024-tick active lifetime ceiling. At normal speed this is 1,200 units initially plus 300 per diamond, reaching 16 seconds after four diamonds and 24 seconds after eight. Rules 14 and 15 used 80 ticks initially plus ten per diamond. Collection extends every surviving active segment by the lifetime increase, and new segments use the upgraded lifetime on the same tick. Expiry still runs before collection, so removed trail is never restored. Power and trail reset each round; rule 17 replaces permanent eliminated trails with decay, described below. Blast/reload progression is unchanged. No snapshot fields or transport envelopes change, but deterministic simulation does: rule equality rejects older peers and snapshots. ## Round shot log

Fold rules `fuse-p2p-15` introduced the following, retained in rules 17 and 18. Game state requires `shots`, the current round's trigger pulls: each entry
is `{ shot, shooterId, weapon, elapsed, bombs, power, extraBombs, fuseLevel, grip, kills: [{ victimId, elapsed }] }`,
where `shot` is the id of the first bomb the pull launched, `weapon` is one of `bomb`, `triple`, `five`, `target`,
`gun`, `shell`, `elapsed` counts ticks into the round, and `bombs` through `grip` record what the pull
launched and the shooter's upgrades at that moment. A bomb carries an optional `shot` naming its pull. Game state
also carries an optional `decidedRound` — `{ matchId, round, tick, shots, rating? }` — written when a round is decided and
kept until the next round is decided, through a rematch and a return to the lobby. Its `shots` leave out pulls
that killed nobody and still had a bomb in the air at the decision, which the round's end interrupted. Nothing in
the simulation reads any of this; it exists so product analytics can report one `Kill` per kill and one `Miss`
per pull that killed nobody (see [product analytics](../ANALYTICS.md)).

`shots` is cleared at the start of every round, because bomb ids restart there, and capped at 512 pulls. Public
snapshots carry only `decidedRound`, never the round in play; the reporting device waits until its runtime's
`confirmedTick()` — every connected rider's input confirmed — reaches `decidedRound.tick`, because the snapshot it
renders is its own prediction. LAN phone controller snapshots strip `decidedRound`. A bomb's `shot` reaches no
snapshot; it travels only in checkpoints, and the shot of a blast lives on the copy `resolveExplosions` hands its
caller for one tick's kill attribution.

Checkpoint decoding rejects, in either log, an unknown weapon, a zero or duplicated pull id, a rider killed by its
own pull or twice in a round, a kill logged before its pull, more than four kills on one pull, a pull of zero bombs
or more than a volley can hold, upgrades outside their caps, and more than 512 pulls. The round in play must also
name issued pull ids and riders with match statistics, and be empty in the lobby; a bomb may not name a pull issued
after it. `decidedRound` may name riders and bomb ids that no longer exist, since it outlives the round and the
match, but may not be decided after the current tick, or name a round of this match not yet played. A bomb with
no `shot` is accepted so a missing one never becomes a wrong one — its kill is simply not logged. Both logs enter
the canonical state hash, so rule equality rejects older peers and snapshots: refresh all peers together, and use
fresh rooms after rollback. Room-service and transport envelopes are unchanged.

### Detached trail decay (#213)

Fold rules `fuse-p2p-17` combined the shot log, eight-second Power trails and slower detached-trail decay. Ordered trail segments carry optional
`detached: { id, decayStartTick }`; absence means the living, age-limited active tail.
The required game-state `nextTrailPieceId` issues positive, round-scoped piece ids across
all riders. Segments in each detached piece are consecutive, touching, ordered history,
with one clock and owner. Crossings never reconnect pieces. Portal transit preserves
active logical continuity, but separate drawable runs become separate pieces on death
or destructive detachment. Coordinates and original creation/expiry ticks remain intact.

Blasts (including same-tick Target releases), gun holes and closing walls keep only the
head-linked surviving suffix active; older surviving runs detach. Death, including leave,
detaches all active runs and retained fatal-contact geometry. Detachment records
`decayStartTick = cutOrDeathTick + 20`. Geometry stays fixed through that tick; each
subsequent playing tick consumes 1.875 world units from each end before weapons/collision.
Each end now shrinks at 37.5 units/second: a 300-unit piece lasts five seconds total, including the pause, instead of three. Child pieces inherit the original clock when recut. Death never refreshes old debris.
Decay ignores original expiry and owner speed/boost/Power; only active segments receive
Power lifetime extensions. Non-playing phases freeze trail geometry, and round reset
clears it and resets piece allocation. The current 160-tick base and 40 ticks per Power pickup remain.

Each rider is bounded to 2,048 total segments/pieces; saturation drops oldest detached
segments before touching active capacity. Runtime validation rejects unknown metadata,
unissued/duplicate/noncontiguous ids, mismatched schedules, future detachment, unordered
history and over-limit arrays before atomic snapshot installation. The existing byte and
parser budgets also apply. Snapshots/checkpoints and LAN presentation all carry the same
geometry. Bots ignore detached segments' obsolete expiry timestamps. Both Phaser backends
render detached/dead trails at 60% opacity; cosmetic flying fragments remain separate.

Peer hello and snapshot rules equality rejects older builds. Refresh all peers together;
there is no live-room migration. Start fresh rooms when rolling back. This change does
not deploy production or change packet transport envelopes.

## Survival scoring

Fold rules `fuse-p2p-18` introduced survival scoring, retained in rule 19. Matches now default to five rounds and rank by match survival points, then round wins, sharing any remaining tie. One point is awarded per strictly earlier elimination, plus one for the sole survivor. Same-tick deaths and timeout survivors do not outlast each other. Match statistics retain `matchScoreUnits` independently of session totals, including departed participants; checkpoints require that field. Presentation snapshots include `matchLength` and each seated rider's `matchScoreUnits` and `roundScoreUnits`. Round scores are applied exactly once at round end. Shared champions each receive a session match win; `matchWinnerId` remains absent when there is more than one champion, and the recap identifies champions by placement 1. Browser preferences from the old wins format migrate to five rounds; wire settings only accept rounds. Refresh every peer together; old rules and snapshots are incompatible, and rollback requires fresh rooms.

## Round speed ramp

Fold rules `fuse-p2p-19` introduced the round speed ramp. Each tick, riders move and steer at `roundSpeedMultiplier(tick - roundStartedTick)` times the base rate: 1× at the start of the round, rising linearly to 1.5× at `OVERTIME_START_TICK`, then held until the round ends. Boost multiplies distance only, on top of the ramp. The multiplier comes from `tick` and `roundStartedTick`, which snapshots and checkpoints already carry, so that change added no wire or checkpoint field. Older peers would move riders at the old speed and fold the same log into a different world, so the rules string rejects them. Refresh every peer together, and start fresh rooms after a rollback.

## Instant Gun

Fold rules `fuse-p2p-20` introduced Instant Gun. Gun consumes `press` and resolves a straight ray after turn/move and all launches in the same tick. Every shot sees the same committed heads/trails before cuts and deaths; nearest contact wins, with slot order breaking equal rider contacts. Heads, living/dead trails and walls stop shots; the shooter’s own body is ignored. Body impacts cut a radius-14 disk. An impact within 18 units of that body’s living head is lethal, respecting shield and temporary immunity. There is no splash or homing. Triple/Five/Extra Bomb still fan out, and normal reload applies. Release/cancel cannot undo or repeat a fired shot.

Existing `shell.gun` bomb records now carry harmless 3-tick tracers: launch coordinates are the ray origin, `x/y` its resolved endpoint, and `vx/vy` a unit heading. They never move, explode, block the next shot or mark a shot unresolved in the round log. Headshot kills use the existing explosion death category and gun shot attribution. No fields or transport envelopes changed, but old simulation rules are incompatible: refresh every peer together and start fresh rooms after rollback.

## Persistent map pickups

Fold rules `fuse-p2p-21` made map pickups persistent. Uncollected pickups last until round reset, with `expiresAtTick` set to `Number.MAX_SAFE_INTEGER` so existing finite snapshot/checkpoint fields and sprite opacity remain valid. Pickup expiry no longer runs. Every newly resolved bomb blast destroys pickups whose centers are strictly within 60% of its radius (more than 40% of the radius inward from the edge). The exact boundary and outer blast fringe survive. This includes chained, Target and Singularity bombs; lingering blast visuals, gravity fields, shells and Gun tracers do not destroy pickups. Collection still precedes explosions within a tick. The living-rider spawn cap remains unchanged, so a full board pauses spawning until slots open. Round preparation clears remaining pickups.

No snapshot fields or transport envelopes change. Rules equality rejects older peers and snapshots because the same inputs now leave different pickups on the board. Refresh all peers together and start fresh rooms after rollback; there is no live-room migration.

## Projectiles through portal gates

Fold rules `fuse-p2p-22` carried projectiles through portals. A Green Shell and a Gun ray now carry through a portal gate the way a rider does, entering at the first gate met and leaving beside its partner at the same proportional height, keeping heading, speed and a shell's bounce count. Lobbed, Target and Singularity bombs do not: they resolve against a landing point rather than travelling, and are unchanged.

A shell's tick is integrated in two passes split at the gate, so a bounce falling on either side of it still resolves against the wall or trail it actually met, and the teleport itself is not swept for rider contact — a rider standing between two gates is not in the shell's way. A shell carries its own `portalCooldownUntilTick`, a new optional `BombState` and checkpoint field of the same shape as the rider's, so a pair it is aimed down cannot hold it in a loop. It reaches a joiner with the rest of the simulation, since the peer snapshot is the checkpoint codec; it is absent only from the render snapshot, which carries what a screen draws. Presentation projects a shell forward from its own velocity and needs no interpolation guard.

A Gun ray is still resolved on the press tick. It may cross at most one gate per pair, so at most `MAX_PORTAL_PAIRS` hops, and each stretch past a gate gets its own 3-tick tracer record carrying the same owner and shot — the renderer keeps drawing every tracer as one straight line. Continuation tracers report no `bombPlaced` event and no placement statistic; the trigger was pulled once. Portal transits by a projectile are not counted as the owner's portal jumps.

Projectile exits are refused only by arena bounds and by foreign portal walls, not by the rider rule: a projectile has no problem appearing beside a rider or a trail. A shell put down on a rider resolves against them in that same tick with no swept travel; one put down in a trail bounces off it from the next. A refused exit leaves the projectile travelling as though the gate were not there.

No snapshot fields or transport envelopes change. Rules equality rejects older peers and snapshots because the same inputs now put projectiles in different places. Refresh all peers together and start fresh rooms after rollback; there is no live-room migration.

### History agreement metadata (`fuse-p2p-25`)

The game freezes `matchFinishers` at the tick it enters `matchOver`: connected seated players with match stats.
Snapshots and validated checkpoints carry this list even if a player leaves or returns during the recap.
A rematch or lobby reset clears it. History reports include its human subset as `finishers`; only these riders'
attestations count toward the majority. Historical participants may still submit and link their own account.
This avoids treating `earlyExits` (an elimination statistic) as presence and avoids disagreement caused by
reading a mutable recap roster. Historical result rosters allow repeated slots and up to 128 distinct riders,
canonicalized by slot then player ID; movement distances retain their bounded fractional values.

The checkpoint schema changes, so rules move from 24 to 25. Old peers and checkpoints are rejected by rule
equality; refresh peers together and use fresh rooms after rollback. Existing gameplay inputs, physics and
room-service signalling envelopes are unchanged. The new history endpoint requires `finishers`; this feature
has not yet been released, so older development history records are not migrated.

### Deterministic iteration (`fuse-p2p-32`)

Player traversal uses slot then codepoint-ordered ID, bombs use numeric ID, and weighted pickup selection uses the fixed `PICKUP_TYPES` order rather than the object's insertion order. Pickups and arena obstacles are arrays the engine generates in id order; every read whose result depends on order (pickup collection and bot targeting, a rider's first scenery contact and with it the obstacle a shield turns away from, the scenery a gun ray stops at, the walls a shell reflects from) sorts by id first, because each contact bisection starts from the contact found before it and so decides its low bits. Locale comparisons and native exponentiation are excluded from engine source. Replicas restored from equivalent checkpoints therefore make the same first-wins choices even when their maps or weight objects were constructed in different orders.

Rules advance from 31 to 32, the current rules; everything rules 25 to 31 introduced (history agreement metadata, arena maps, the Beer stagger, frozen rating standings, the final-round result pause and the aiming slowdown) is preserved. #270 added optional per-rider `combat` statistics to the folded and checkpointed match statistics under an unchanged `fuse-p2p-27`, so a rules-27 peer from before #270 and one from after it hash the same log differently; rules 28 was the first version to separate them from both, and the golden replay now fails any such change that arrives without a version of its own. No additional checkpoint fields or transport envelopes change. Existing rules-equality checks reject older peers and checkpoints; refresh all peers together and use fresh rooms after rollback. This change is not a production deployment.
